# План переезда Obsidian-хранилища на VPS с зеркалом в GitHub

Дата: 2026-09-24.
Связанная база знаний: `wiki/` (Obsidian vault по теме вайбкодинга).

## Цель

Поднять Obsidian-хранилище вайбкодинг-базы на VPS, держать его исходники в Git-репозитории на GitHub как зеркало, бэкап и историю изменений. Сохранить иммутабельность `raw/`, поддерживаемость `wiki/`, прозрачность всех операций.

---

## Фаза 0. Решения до старта

0.1. **Путь на VPS** — `/opt/vault/Вайбкодинг` или `/home/vault/vaults/Вайбкодинг`. Не корень диска, не `~` админа.

0.2. **Владелец vault** — отдельный непривилегированный пользователь `vault`, не `root`. Для SSH-доступа и cron-задач.

0.3. **Git-remote** — один приватный репозиторий на GitHub, например `alexsota/vaybcoding-vault`. Branch `main` — продакшен, при необходимости `draft` для экспериментов.

0.4. **Что НЕ коммитим** — `.obsidian/workspace.json` (ломает синхронизацию при нескольких клиентах), `.obsidian/cache/`, временные файлы, `.env` если появятся.

0.5. **Режим работы** — один основной рабочий vault (например, на рабочем ноуте) + VPS как «эталон + история», иногда мобильный. Несколько одновременных редакторов = rebase-стратегия, разбор конфликтов вручную.

0.6. **SSH-доступ** — только ключ (не пароль), с VPS на GitHub через `~/.ssh/config` + `git@github.com`.

## Фаза 1. Репозиторий на GitHub (15 минут)

1.1. Создать приватный репозиторий `vaybcoding-vault`. **Без** README, .gitignore, лицензии — пустой.

1.2. **Collaborators & teams** → доступ только себе. Если планируется совместная работа — пригласить конкретных людей.

1.3. **Branches → Branch protection rules** для `main`:
- Require linear history.
- Do not allow force pushes.
- (Опционально) Require pull request reviews.

1.4. **Settings → Developer settings → Personal access tokens → Fine-grained tokens** создать токен `vps-vault` с правами `Contents: Read and write` только на этот репозиторий. Срок жизни — 90 дней, потом обновлять.

## Фаза 2. Подготовка локальной копии (10 минут, на текущей машине)

2.1. Убедиться, что в `raw/` нет чувствительных или лишних файлов.

2.2. Создать файл `.gitignore` в корне vault:

```gitignore
# Obsidian
.obsidian/workspace.json
.obsidian/cache/
.obsidian/plugins/*/data.json

# System
.DS_Store
Thumbs.db
desktop.ini

# Temp
*.swp
*.swo
*~
*.tmp

# Secrets (if any appear later)
.env
*.key
*.pem

# Logs
*.log
node_modules/
```

2.3. `.obsidian/` в целом коммитится (настройки, плагины, темы — это часть vault). Игнорируем только локальные кэши и workspace.json.

2.4. Проверить, что `raw/online/` — только `.md`. Сейчас так.

2.5. Инициализировать Git и первый коммит:

```bash
cd <путь-к-vault>
git init
git add .
git commit -m "Initial vault snapshot: raw, wiki, reports"
```

2.6. Подключить remote и запушить:

```bash
git remote add origin git@github.com:alexsota/vaybcoding-vault.git
git branch -M main
git push -u origin main
```

2.7. На GitHub убедиться, что все файлы уехали, размер репозитория разумный (< 100 МБ). Если больше — посмотреть, не затесались ли бинарники.

## Фаза 3. Подготовка VPS (30–60 минут)

3.1. **Выбор тарифа:**
- Минимум: 1 vCPU, 1 ГБ RAM, 20 ГБ SSD.
- Рекомендую: 2 vCPU, 2 ГБ RAM, 40 ГБ SSD.
- Где: Amvera Cloud (знакомый стек, есть в базе), Selectel, Timeweb, или любой другой. Регион — Варшава/Москва в зависимости от доступов.

3.2. Создать VPS, получить IP и root-доступ (по паролю в первый раз, **сразу сменить пароль**).

3.3. Базовые пакеты:

```bash
ssh root@<IP>
apt update && apt upgrade -y
apt install -y git curl vim ufw fail2ban
```

3.4. Создать пользователя `vault`:

```bash
adduser vault
usermod -aG sudo vault
mkdir -p /home/vault/.ssh
```

3.5. Сгенерировать пару ключей на VPS для GitHub:

```bash
sudo -u vault ssh-keygen -t ed25519 -C "vps-vault-$(hostname)" -f /home/vault/.ssh/github
chmod 600 /home/vault/.ssh/github
chmod 700 /home/vault/.ssh
chown -R vault:vault /home/vault/.ssh
```

3.6. Публичный ключ `/home/vault/.ssh/github.pub` добавить в GitHub → **Settings → SSH and GPG keys → New SSH key**:
- Title: `VPS <hostname> vault access`.
- Key type: Authentication.

3.7. `~/.ssh/config` для удобства:

```bash
sudo -u vault tee /home/vault/.ssh/config <<'EOF'
Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/github
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new
EOF
chown vault:vault /home/vault/.ssh/config
chmod 600 /home/vault/.ssh/config
```

3.8. Проверить соединение с GitHub:

```bash
sudo -u vault ssh -T git@github.com
```

Ожидаемый ответ: `Hi <username>! You've successfully authenticated...`

3.9. Закрыть root-доступ по паролю:

```bash
sed -i 's/PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart sshd
```

3.10. Настроить firewall:

```bash
ufw allow OpenSSH
ufw enable
ufw status
```

3.11. Сменить SSH-порт (опционально, рекомендую):

```bash
sed -i 's/#Port 22/Port 22022/' /etc/ssh/sshd_config
ufw allow 22022/tcp
ufw delete allow OpenSSH
systemctl restart sshd
```

После этого подключаться: `ssh -p 22022 vault@<IP>`.

## Фаза 4. Клонирование vault на VPS (5 минут)

4.1. Подключиться под `vault`:

```bash
ssh -p 22022 vault@<IP>
```

4.2. Создать целевую папку и клонировать:

```bash
sudo mkdir -p /opt/vault
sudo chown vault:vault /opt/vault
git clone git@github.com:alexsota/vaybcoding-vault.git /opt/vault/Вайбкодинг
cd /opt/vault/Вайбкодинг
git status
```

4.3. Настроить Git-конфиг пользователя `vault`:

```bash
git config --global user.name "Vault Bot"
git config --global user.email "vault@<domain-or-empty>"
git config --global pull.rebase true
git config --global init.defaultBranch main
```

4.4. Проверить, что vault доступен и читаем:

```bash
ls -la
cat index.md
```

## Фаза 5. Автоматическая синхронизация VPS ↔ GitHub (опционально, 20 минут)

5.1. **Если правим только вручную** — этот раздел можно пропустить.

5.2. **Автоматический pull каждые 30 минут** через cron:

```bash
crontab -e
```

```cron
# Pull vault from GitHub every 30 minutes
*/30 * * * * cd /opt/vault/Вайбкодинг && git pull --rebase --autostash >> /home/vault/vault-sync.log 2>&1
```

5.3. **Push из VPS в GitHub — только ручной**, через Obsidian или `git commit && git push`. Не делаем push из cron — иначе при конфликтах будут проблемы.

5.4. **Pre-push hook** для безопасности:

```bash
mkdir -p .git/hooks
cat > .git/hooks/pre-push <<'EOF'
#!/bin/bash
# Block .env and .key files
if git diff --cached --name-only | grep -E '\.(env|key|pem)$'; then
  echo "Refusing to push sensitive file"
  exit 1
fi
EOF
chmod +x .git/hooks/pre-push
```

## Фаза 6. Доступ к vault с разных устройств (10 минут на каждое)

6.1. **Локальный компьютер (Obsidian):**
- `git clone git@github.com:alexsota/vaybcoding-vault.git`.
- Открыть в Obsidian как vault.
- `.gitignore` локально (как в Фазе 2.2).
- **Один основной рабочий vault** на одном устройстве (например, рабочий ноут), VPS как «эталон + история».

6.2. **Obsidian Sync / Remotely Save** (опционально для live-синхронизации):
- Obsidian Sync (платный) — шифрует, синхронизирует vault на всех устройствах.
- **Remotely Save** (бесплатный плагин) — синхронизация через S3/WebDAV. Можно поднять на том же VPS.
- Проще: `git pull && git push` перед/после сессии.

6.3. **Мобильный Obsidian** — клонировать через Termux или плагин `git` для Obsidian. Для чтения достаточно `git pull` раз в день.

6.4. **Через браузер (без Obsidian):**
- Поднять на VPS `caddy` или `nginx` + статический сайт из сгенерированного HTML.
- Проще: **Quartz** (open-source, рендерит Obsidian в статический сайт) — `npx quartz create`, пушит в `gh-pages` ветку.

## Фаза 7. Бэкап и аварийное восстановление (30 минут)

7.1. **Snapshot VPS** — у большинства провайдеров есть автоматические snapshot'ы. Включить раз в сутки, хранить 7 штук.

7.2. **Бэкап GitHub** — `git clone` сам по себе бэкап. История коммитов — это и есть бэкап. Рекомендую делать **push хотя бы раз в день активной работы**.

7.3. **Зеркало на другом хосте** (опционально) — раз в неделю `git clone` на локальный компьютер. Три копии: VPS, GitHub, локальный комп.

7.4. **Восстановление после сбоя VPS:**

```bash
ssh vault@<новый-IP>
git clone git@github.com:alexsota/vaybcoding-vault.git /opt/vault/Вайбкодинг
```

Всё, vault на месте. История сохранена в Git.

## Фаза 8. CI/CD (опционально, 1 час)

8.1. **GitHub Actions для линта wiki** — на каждый push запускать проверку orphan-ссылок, противоречий, broken links.

Файл `.github/workflows/wiki-lint.yml`:

```yaml
name: Wiki lint
on:
  push:
    branches: [main]
    paths: ['wiki/**']
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check orphan pages
        run: |
          for f in wiki/**/*.md; do
            echo "Checking $f"
          done
```

8.2. **MkDocs build → Pages** — автосборка сайта из `wiki/` и публикация на GitHub Pages.

## Что делать, если что-то пошло не так

| Проблема | Решение |
| --- | --- |
| `Permission denied (publickey)` при `git clone` | Проверить, что публичный ключ VPS добавлен в GitHub, и `~/.ssh/config` указывает на правильный ключ |
| Конфликт при `git pull` | `git status` → посмотреть файлы → `git checkout -- <файл>` или разрешить вручную |
| Push отклонён GitHub (branch protection) | Через Pull Request или временно снять protection |
| VPS недоступен | Зайти через консоль провайдера, проверить `systemctl status sshd`, `ufw status` |
| Случайно запушили `.env` | Срочно: `git filter-repo` + сменить все ключи |
| Забыли сделать push перед поездкой | На любом устройстве: `git clone` — vault на момент последнего push |

## Что НЕ покрыто этим планом

- **Автоматический merge конфликтов** — невозможно безопасно, решается вручную.
- **Шифрование vault at rest на VPS** — ответственность провайдера; для приватного vault на своём VPS достаточно SSH + firewall.
- **CRDT/live-синхронизация** — это Obsidian Sync / Remotely Save, отдельная тема.
- **CI для рендера сайта** — Quartz/MkDocs, опционально.
