# План переезда AI-агента (pi-coding-agent) с ноутбука на VPS

Дата: 2026-09-24.
Связанный план: `задумки-проект/2026-09-24-план-переезда-на-vps.md` (переезд vault'а — отдельная задача, но эти два плана пересекаются и должны выполняться вместе).

## Цель

Перенести AI-агент-ассистент (pi-coding-agent с обвязкой pi-ai / pi-agent-core) с рабочего ноутбука на VPS так, чтобы:

- агент работал круглосуточно (не «умирал» при закрытии ноутбука);
- весь накопленный контекст, история сессий, log.md, MCP-конфиги, custom-skills переехали без потерь;
- vault с `raw/`, `wiki/`, `Отчет/`, `задумки-проект/` хранился и обновлялся в GitHub (origin);
- доступ к агенту — через SSH (CLI) и/или через web-gateway (TUI/UI);
- безопасность на уровне: ключи только, sandbox для tool-вызовов, fail2ban, отдельный пользователь.

## Что считаем «агентом»

Под «агентом» в этом плане понимается:

1. **Среда выполнения** — `pi-coding-agent` (CLI от earendil-works) с зависимостями `pi-ai`, `pi-agent-core`.
2. **LLM-конфиг** — провайдеры моделей (OpenRouter, OpenAI, Anthropic), ключи, model_overrides.
3. **Контекст и память** — `AGENTS.md`, `SOUL.md`, `CLAUDE.md`, `log.md`, история сессий, Skills.
4. **Tool/MCP-конфиг** — `.mcp.json` или эквивалент, custom tools.
5. **Vault** — `raw/`, `wiki/`, `Отчет/`, `задумки-проект/`, `index.md`.
6. **Окружение** — Node 24+, Python 3.11+, ripgrep, ffmpeg, git, и т. п.

## Принципы

- **Сначала vault, потом агент.** Vault — это данные, агент — это «мозг», который с ними работает. Vault должен быть на VPS первым (по плану `2026-09-24-план-переезда-на-vps.md`).
- **GitHub — единый источник истины** для vault. VPS — рабочая копия. Ноутбук — дополнительная копия.
- **Конфиги агента в Git** там, где они не содержат секретов. Секреты — только в `~/.config/pi/` или env-переменных, **не в репо**.
- **Smoke-test перед выключением ноутбука.** До переезда ноутбук остаётся «source of truth», пока не убедимся, что VPS работает идентично.

## Фаза 0. Решения до старта

0.1. **Провайдер VPS** — Amvera Cloud, Selectel, Timeweb, или любой другой. Требования: 2+ vCPU, 2+ ГБ RAM, 30+ ГБ SSD, **доступ к зарубежным API** (если используется OpenAI/Anthropic/OpenRouter) — Варшава или аналогичный регион. Для OpenRouter/Amvera с проксированием — Москва тоже подойдёт.

0.2. **Регион** — Варшава, если важна стабильность связи с зарубежными LLM-API. Москва — если основной LLM-провайдер российский (YandexGPT, GigaChat).

0.3. **Режим работы агента:**
- **Вариант A — CLI по SSH.** Подключаешься по SSH, запускаешь `pi` в TUI-режиме, общаешься через терминал. Самый простой и безопасный.
- **Вариант B — Web-gateway.** На VPS поднимается HTTP/WebSocket-интерфейс (Tauri/Quasar/самописный), агент работает в фоне, доступ через браузер.
- **Вариант C — Telegram-бот.** Hermes-подобный gateway: ты пишешь агенту в Telegram, он отвечает и работает с vault через Git.

Рекомендую начать с **Вариант A (CLI по SSH)**. Если нужно «из любой точки мира и с телефона» — добавить B или C как фазу 11.

0.4. **Один пользователь или несколько?** — Рекомендую `agent` как отдельного пользователя (по аналогии с `vault`). Если ты будешь логиниться под `agent` по SSH, всё под этим пользователем.

0.5. **Секреты** — все API-ключи хранить в `~/.config/pi/secrets.env` с правами 600. Не в репо, не в `wiki/`, не в shell history. На ноутбуке и VPS — **отдельные** secrets, но с одинаковой структурой файла.

0.6. **Частота работы** — агент 24/7 или запускается по запросу? Если 24/7 — нужен systemd-unit. Если по запросу — можно без него.

## Фаза 2. Подготовка VPS-среды (30 минут)

2.1. Создать пользователя `agent`:

```bash
ssh -p 22022 root@<VPS_IP>
adduser agent
usermod -aG sudo agent
mkdir -p /home/agent/.ssh
```

2.2. Сгенерировать SSH-ключ **на VPS** для доступа к GitHub:

```bash
sudo -u agent ssh-keygen -t ed25519 -C "vps-agent-$(hostname)" -f /home/agent/.ssh/github
chmod 600 /home/agent/.ssh/github
chmod 700 /home/agent/.ssh
chown -R agent:agent /home/agent/.ssh
```

2.3. Публичный ключ добавить в GitHub → **Settings → SSH and GPG keys** (Title: `VPS agent`).

2.4. `~/.ssh/config`:

```bash
sudo -u agent tee /home/agent/.ssh/config <<'EOF'
Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/github
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new
EOF
chown agent:agent /home/agent/.ssh/config
chmod 600 /home/agent/.ssh/config
```

2.5. Проверить:

```bash
sudo -u agent ssh -T git@github.com
```

Ожидаемый ответ: `Hi <username>! You've successfully authenticated...`

2.6. Установить runtime:

```bash
apt update && apt upgrade -y
# Node 24 (рекомендуется для pi-coding-agent)
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
apt install -y nodejs
node --version   # ожидаем v24.x

# Python 3.11+ (для части tooling)
apt install -y python3 python3-pip python3-venv

# Утилиты
apt install -y git curl ripgrep fd-find jq tmux htop ufw fail2ban
```

2.7. Создать рабочую папку агента:

```bash
sudo mkdir -p /opt/agent/work
sudo chown agent:agent /opt/agent/work
```

2.8. Закрыть root-доступ по паролю, оставить только по ключу:

```bash
sed -i 's/PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart sshd
```

## Фаза 3. Экспорт конфигов агента с ноутбука (10 минут)

3.1. На ноутбуке найти, где лежат конфиги `pi-coding-agent`:

```bash
# Типичные пути:
ls -la ~/.config/pi/ 2>/dev/null
ls -la ~/.pi/ 2>/dev/null
ls -la ~/.pi-coding-agent/ 2>/dev/null

# Проверить переменные окружения
env | grep -i -E 'PI_|ANTHROPIC|OPENAI|OPENROUTER'
```

3.2. Составить список того, что **нужно** перенести:
- `~/.config/pi/config.json` или эквивалент (настройки провайдеров, без секретов).
- `~/.config/pi/secrets.env` (API-ключи) — **копируется вручную, не в Git**.
- `~/.config/pi/agents/*.md` (custom AGENTS.md / SOUL.md / skills).
- `~/.config/pi/mcp/*.json` (MCP-конфиги).
- История сессий — обычно в SQLite или JSON в `~/.config/pi/sessions/`.

3.3. **НЕ переносить** через интернет (только вручную через `scp`):
- API-ключи.
- Любые `.env` файлы.
- `auth.json`, `tokens.json`, `credentials.json`.

3.4. Сохранить список путей в файл (на ноутбуке):

```bash
cat > /tmp/agent-export-paths.txt <<'EOF'
# Перенести в /home/agent/.config/pi/ на VPS
~/.config/pi/config.json
~/.config/pi/agents/
~/.config/pi/mcp/
~/.config/pi/skills/
# История сессий (опционально — можно начать с чистой)
~/.config/pi/sessions/
EOF
```

3.5. Создать архив того, что можно безопасно положить в Git (без секретов):

```bash
tar -czf /tmp/pi-config-public.tar.gz \
  -C ~/.config/pi \
  --exclude='secrets.env' \
  --exclude='*.key' \
  --exclude='auth.json' \
  config.json agents/ mcp/ skills/
```

3.6. Скопировать архив на VPS:

```bash
scp -P 22022 /tmp/pi-config-public.tar.gz agent@<VPS_IP>:/tmp/
```

3.7. Секреты (`secrets.env`, ключи) скопировать **отдельной командой** через `scp` с явным удалением из истории:

```bash
scp -P 22022 ~/.config/pi/secrets.env agent@<VPS_IP>:/home/agent/.config/pi/secrets.env
ssh -p 22022 agent@<VPS_IP> "chmod 600 /home/agent/.config/pi/secrets.env"
```

3.8. Удалить архивы и временные файлы:

```bash
rm /tmp/pi-config-public.tar.gz /tmp/agent-export-paths.txt
```

## Фаза 4. Установка pi-coding-agent на VPS (15 минут)

4.1. Установить через `npm` (для CLI):

```bash
sudo -u agent bash -c 'cd /opt/agent && npm init -y && npm install -g pi-coding-agent@latest'
```

Если глобальная установка запрещена — использовать `npx`:

```bash
sudo -u agent bash -c 'cd /opt/agent && npm init -y && npm install pi-coding-agent@latest'
alias pi='/opt/agent/node_modules/.bin/pi'
```

4.2. Альтернатива — клонировать исходники из GitHub (если нужна конкретная версия или модифицированная сборка):

```bash
sudo -u agent git clone https://github.com/earendil-works/pi-coding-agent.git /opt/agent/pi-coding-agent
sudo -u agent bash -c 'cd /opt/agent/pi-coding-agent && npm install && npm run build'
```

4.3. Восстановить конфиги:

```bash
sudo -u agent bash -c '
mkdir -p ~/.config/pi
cd /tmp
tar -xzf pi-config-public.tar.gz -C /tmp/pi-restore/
mkdir -p ~/.config/pi
cp -r /tmp/pi-restore/* ~/.config/pi/
chmod 700 ~/.config/pi
chmod 600 ~/.config/pi/secrets.env
rm -rf /tmp/pi-restore /tmp/pi-config-public.tar.gz
'
```

4.4. Скопировать vault:

```bash
sudo -u agent git clone git@github.com:alexsota/vaybcoding-vault.git /opt/agent/work/Вайбкодинг
```

4.5. Проверить, что агент видит vault:

```bash
sudo -u agent /opt/agent/node_modules/.bin/pi --vault /opt/agent/work/Вайбкодинг --status
```

4.6. **Smoke-test 1:** запустить `pi` в интерактивном режиме, попросить сделать что-то простое:

```
> Список файлов в raw/Clippings/
```

Если ответ корректный — установка прошла успешно.

## Фаза 5. Systemd-unit для круглосуточной работы (опционально, 20 минут)

> Только если выбран **Вариант A** в Фазе 0.3 (агент 24/7) **или Вариант B/C** (gateway).

5.1. Создать unit-файл:

```bash
sudo tee /etc/systemd/system/agent.service <<'EOF'
[Unit]
Description=AI Agent (pi-coding-agent)
After=network.target

[Service]
Type=simple
User=agent
Group=agent
WorkingDirectory=/opt/agent/work/Вайбкодинг
Environment="HOME=/home/agent"
EnvironmentFile=/home/agent/.config/pi/secrets.env
ExecStart=/opt/agent/node_modules/.bin/pi --vault /opt/agent/work/Вайбкодинг --rpc --port 18789
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal

# Ограничения безопасности
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/opt/agent/work /home/agent/.config/pi
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6
RestrictNamespaces=true
RestrictRealtime=true
SystemCallArchitectures=native
SystemCallFilter=@system-service

[Install]
WantedBy=multi-user.target
EOF
```

5.2. Включить и запустить:

```bash
sudo systemctl daemon-reload
sudo systemctl enable agent
sudo systemctl start agent
sudo systemctl status agent
```

5.3. Проверить логи:

```bash
sudo journalctl -u agent -f
```

5.4. **Smoke-test 2:** подключиться к RPC-порту из локального CLI:

```bash
pi --rpc-endpoint http://<VPS_IP>:18789 --status
```


6.3. Мобильный доступ (Termux на Android или Blink на iOS):


## Фаза 7. Безопасность и секреты (20 минут)

7.1. **Файл секретов `~/.config/pi/secrets.env`** с правами 600:

```bash
chmod 600 /home/agent/.config/pi/secrets.env
chown agent:agent /home/agent/.config/pi/secrets.env
ls -la /home/agent/.config/pi/secrets.env   # -rw------- agent agent
```

7.2. **Никогда** не коммитить secrets в Git. Проверить:

```bash
cd /opt/agent/work/Вайбкодинг
git status
# Убедиться, что ничего секретного не появилось
```

7.3. **Все API-ключи на ноутбуке и VPS — разные.** Если VPS скомпрометирован — отзываем только VPS-ключ.

7.4. **fail2ban** для SSH:

```bash
sudo systemctl enable fail2ban
sudo systemctl start fail2ban
```

7.5. **SSH-порт нестандартный** (если не сделано в плане vault) — повторить шаг 3.11 из плана vault.

7.6. **Sandbox для tool-вызовов агента.** Если агент может выполнять shell-команды (а он может), добавить:

- Все команды, которые могут удалить файлы (`rm -rf`, `dd`, `chmod 777`), — запрещены в `AGENTS.md` или через whitelist в MCP-конфиге.
- Каждая сессия — отдельный git worktree, чтобы не загрязнить основной vault.
- Pre-commit hook (если хочешь автозащиту):

```bash
mkdir -p .git/hooks
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/bash
# Block committing sensitive files
if git diff --cached --name-only | grep -E '\.(env|key|pem)$'; then
  echo "Refusing to commit sensitive file"
  exit 1
fi
EOF
chmod +x .git/hooks/pre-commit
```

7.7. **Логирование** — все сессии агента писать в journald (если через systemd) или в файл:

```bash
sudo mkdir -p /var/log/agent
sudo chown agent:agent /var/log/agent
```


9.6. **Долгая сессия** — запустить `tmux`, в нём `pi`, отключиться от SSH на 5 минут, подключиться снова, проверить, что сессия жива.

## Что делать, если что-то пошло не так

| Проблема | Решение |
| --- | --- |
| `pi: command not found` | `which pi` → проверить PATH. Возможно, нужна локальная установка через `npm install` |
| Агент не видит vault | Проверить `--vault` путь, права на чтение для пользователя `agent` |
| LLM-ключ не работает на VPS | Скопировать `secrets.env` заново, проверить `chmod 600` и `EnvironmentFile` в systemd |
| Systemd-unit падает | `journalctl -u agent -n 50` — посмотреть причину |
| Конфликт при `git pull` | `git status` → `git checkout -- <файл>` или разрулить вручную |
| SSH-доступ пропал | Консоль провайдера → проверить `systemctl status sshd`, `ufw status` |
| Забыл секреты на ноутбуке, нужно срочно с VPS | `scp -P 22022 agent@<VPS_IP>:/home/agent/.config/pi/secrets.env .` (осторожно с правами) |

## Что НЕ покрыто этим планом

- **Multi-user agent** — для одного пользователя. Если нужна команда — отдельная настройка прав и аудит.
