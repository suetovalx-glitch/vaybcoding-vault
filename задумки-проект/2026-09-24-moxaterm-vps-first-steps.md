Дата: 2026-09-24.
Назначение: быстро поднять MoxaTerm на Windows, создать SSH-сессию к VPS, и выполнить базовые команды первого входа. После прохождения этого чек-листа — продолжить по плану `2026-09-24-план-переезда-агента-на-vps.md` (Фаза 2: пользователь `agent`, runtime).

## 0. Установить MoxaTerm

0.1. Скачать MoxaTerm (Windows-инсталлятор) с официального сайта Moxa: **https://www.moxa.com/en/products/industrial-computing/system-software/moxa-term** — или через поиск «MoxaTerm download». Подтверди источник, прежде чем качать.

0.2. Запустить инсталлятор, согласиться с UAC (запросит права администратора), установить в `C:\Program Files\Moxa\MoxaTerm\` (по умолчанию).

0.3. Запустить MoxaTerm. При первом запуске предложит создать сессию — закрыть этот мастер, мы создадим вручную с правильными параметрами.

## 1. Сгенерировать SSH-ключ на Windows (если ещё нет)

> **Зачем:** подключаться к VPS по ключу, а не по паролю — это и безопаснее, и удобнее (MoxaTerm подхватит ключ автоматически).

1.1. Открыть **меню Пуск → Командная строка** (cmd) или **PowerShell**.

1.2. Проверить, есть ли уже ключ:

```cmd
dir %USERPROFILE%\.ssh
```

Если видишь `id_ed25519` и `id_ed25519.pub` — ключ уже есть, шаги 1.3–1.5 пропускай.

1.3. Сгенерировать ключ:

```cmd
ssh-keygen -t ed25519 -C "alexsota-$(hostname)" -f %USERPROFILE%\.ssh\id_ed25519
```

1.4. На запрос «Enter passphrase» — рекомендую ввести парольную фразу (это пароль для ключа, не для VPS). Пустую оставлять не стоит.

1.5. После генерации убедиться, что файлы появились:

```cmd
dir %USERPROFILE%\.ssh
```

Должны быть `id_ed25519` (приватный, **никому не давать**) и `id_ed25519.pub` (публичный — его отдаём VPS).

1.6. Скопировать **содержимое** публичного ключа в буфер обмена:

```cmd
type %USERPROFILE%\.ssh\id_ed25519.pub | clip
```

Это понадобится в момент создания VPS — провайдер обычно спрашивает «вставьте публичный ключ».

## 2. Создать VPS

> **Провайдер на выбор (рекомендую — Amvera Cloud, знакомый стек и есть в нашей базе):**
>
> - **Amvera Cloud** — https://amvera.io, регистрация через GitHub или email.
> - **Selectel** — https://selectel.ru.
> - **Timeweb Cloud** — https://timeweb.cloud.
> - **Reg.ru, Beget, и т. д.** — подойдёт любой, у кого есть Ubuntu 22.04+.

2.1. Зарегистрироваться / залогиниться у провайдера.

2.2. Создать новый сервер / виртуальную машину с параметрами:
- **ОС:** Ubuntu 22.04 LTS или 24.04 LTS (рекомендую 24.04).
- **Тариф:** 2 vCPU, 2 ГБ RAM, 30+ ГБ SSD (минимум для агента).
- **Регион:** Варшава (для стабильного доступа к OpenAI/Anthropic/OpenRouter). Если планируешь работать с российскими LLM — Москва.
- **SSH-ключ:** вставить из буфера обмена (см. шаг 1.6) — **обязательно**, иначе придётся заходить по паролю.

2.3. После создания провайдер даст:
- **IP-адрес** (например, `188.166.xxx.xxx`).
- **Логин** (по умолчанию `root` или `ubuntu` — зависит от провайдера).
- **Порт SSH** (по умолчанию 22).

2.4. Записать эти три значения в заметку (IP, логин, порт). Они понадобятся в MoxaTerm.

## 3. Создать SSH-сессию в MoxaTerm

3.1. В MoxaTerm: **File → New Session → SSH**.

3.2. Заполнить поля:

| Поле | Значение |
| --- | --- |
| **Host** | IP-адрес VPS (например, `188.166.xxx.xxx`) |
| **Port** | 22 (или другой, если провайдер дал нестандартный) |
| **Username** | `root` или `ubuntu` (то, что дал провайдер) |
| **Authentication method** | Public key |
| **Private key file** | `C:\Users\AlexSota\.ssh\id_ed25519` |
| **Passphrase** | парольная фраза от ключа (если задавал) |
| **Keep alive** | 60 секунд (включить) |
| **Compression** | отключить |
| **Display** | UTF-8 |
| **Font** | Consolas или Cascadia Code, 14pt |

3.3. Нажать **Save**, дать сессии понятное имя: `vps-имя-провайдера` (например, `vps-amvera`).

3.4. Нажать **Connect** — откроется терминал.

3.5. При первом подключении MoxaTerm покажет fingerprint — подтвердить (`Accept and save`).

3.6. Если всё ОК, увидишь приглашение:

```
root@имя-хоста:~#
```

**Поздравляю, ты на VPS.**

## 4. Первичная настройка (выполнять в MoxaTerm)

### 4.1. Обновить систему

```bash
apt update && apt upgrade -y
```

### 4.2. Установить базовые утилиты

```bash
apt install -y git curl vim ufw fail2ban tmux htop jq ripgrep fd-find
```

### 4.3. Создать пользователя `agent` (под ним будем работать)

```bash
adduser agent
```

Система попросит ввести пароль и доп. информацию. **Пароль запомнить/записать** — это для `sudo`, не для SSH.

```bash
usermod -aG sudo agent
```

Проверить, что `agent` в группе `sudo`:

```bash
groups agent
```

Ожидаемый ответ содержит `sudo`.

### 4.4. Скопировать публичный ключ в `agent` (чтобы логиниться под ним по SSH)

```bash
mkdir -p /home/agent/.ssh
cp ~/.ssh/authorized_keys /home/agent/.ssh/ 2>/dev/null || true
# Если у root нет authorized_keys, скопировать из MoxaTerm через scp — см. ниже
chown -R agent:agent /home/agent/.ssh
chmod 700 /home/agent/.ssh
chmod 600 /home/agent/.ssh/authorized_keys 2>/dev/null || true
```

Если у root нет своего `authorized_keys` (например, провайдер внедрил ключ через cloud-init иначе), проще зайти на VPS, стать root, и из MoxaTerm вставить ключ:

```bash
# Сгенерировать новый ключ прямо на VPS (под root)
ssh-keygen -t ed25519 -C "agent-from-vps" -f /root/.ssh/id_ed25519
# Посмотреть публичный ключ
cat /root/.ssh/id_ed25519.pub
```

Скопировать вывод `cat` и вставить в **локальный файл** `C:\Users\AlexSota\.ssh\id_ed25519.pub.agent` — это пригодится для следующего шага.

Альтернатива — **добавить в `~/.ssh/authorized_keys` агента твой локальный публичный ключ**:

```bash
nano /home/agent/.ssh/authorized_keys
# вставить содержимое id_ed25519.pub с локальной машины (правый клик в MoxaTerm)
chmod 600 /home/agent/.ssh/authorized_keys
chown agent:agent /home/agent/.ssh/authorized_keys
```

### 4.5. Проверить вход под `agent` (не закрывая текущую сессию)

Открыть **вторую** вкладку в MoxaTerm → подключиться к той же сессии, но Username = `agent`. Если вход прошёл по ключу — успех.

### 4.6. Закрыть root-доступ по паролю

```bash
nano /etc/ssh/sshd_config
```

Найти строку `PermitRootLogin` и привести к виду:

```
PermitRootLogin prohibit-password
```

Сохранить (Ctrl+O, Enter, Ctrl+X) и перезапустить SSH:

```bash
systemctl restart sshd
```

> **Важно:** не закрывать текущую сессию, пока не убедишься, что новая (под `agent`) работает.

### 4.7. Сменить SSH-порт (опционально, рекомендую)

```bash
nano /etc/ssh/sshd_config
```

Найти `#Port 22`, раскомментировать и поменять:

```
Port 22022
```

Сохранить, обновить firewall, перезапустить:

```bash
ufw allow 22022/tcp
ufw enable
ufw status
systemctl restart sshd
```

В MoxaTerm **отредактировать сохранённую сессию** — поменять Port на 22022. Подключиться заново.

## 5. Проверить, что всё работает

5.1. В MoxaTerm под `agent` выполнить:

```bash
whoami          # ожидаемо: agent
hostname -I     # IP-адреса VPS
df -h           # свободное место на диске
free -h         # использование RAM
```

5.2. Проверить, что есть интернет:

```bash
curl -I https://github.com
```

Ожидаемо: HTTP/2 200.

5.3. Проверить, что `git` работает с GitHub (на этом этапе ключ ещё не настроен, поэтому подключение может спросить логин):

```bash
git clone https://github.com/earendil-works/pi-coding-agent.git /tmp/test-clone
ls /tmp/test-clone
rm -rf /tmp/test-clone
```

> **Если провайдер блокирует github.com** — клонировать через `git://` или через VPN.

## 8. Если что-то пошло не так

| Проблема | Решение |
| --- | --- |
| MoxaTerm не подключается | Проверить IP, порт, белый список у провайдера. Перезагрузить VPS из панели управления |
| `Permission denied (publickey)` | MoxaTerm не подхватил ключ. Проверить поле «Private key file» в настройках сессии |
| `agent` не может `sudo` | `usermod -aG sudo agent`, потом **перелогиниться** (новая SSH-сессия) |
| После `systemctl restart sshd` всё пропало | Сессия не разорвана — это нормально, ты в той же. Открыть новую вкладку и проверить |
| `github.com` недоступен | Через прокси или VPN. Проверить `curl -I https://github.com` — если таймаут, проблема в сети VPS |
| `apt update` падает с ошибкой GPG | `apt update --allow-releaseinfo-change` либо сменить зеркало на `mirror.yandex.ru` или `archive.ubuntu.com` |
| Случайно закрыл root-сессию, а agent не настроен | Зайти через **веб-консоль провайдера** (VNC/serial console), починить оттуда |
