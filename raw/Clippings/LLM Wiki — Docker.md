## LLM Wiki

Covers Docker Engine и интерфейс командной строки с открытым исходным кодом: контейнеры в сравнении с виртуальными машинами и архитектура клиент/демон/реестр, образы и реестры, Dockerfile (все инструкции), сборка образов с помощью BuildKit (многоэтапная сборка, кэш, секреты, мультиархитектура), интерфейс командной строки Docker, среда выполнения контейнеров и флаги docker run, сетевые драйверы и публикация портов, хранилище (тома/привязки/tmpfs), Docker Compose и compose.Спецификация YAML, демон dockerd и файл daemon.json, REST API Engine и безопасность контейнеров — с дословным синтаксисом Dockerfile, флагами интерфейса командной строки и ключами конфигурации.

Не рассматриваетсяDocker Desktop, Scout, Hub, Build Cloud, а также корпоративные и административные функции; исчерпывающие последовательности команд для установки в каждом дистрибутиве и самые подробные сведения о сетевых технологиях и хранилищах (здесь рассматриваются их концепции и команды, но не каждый шаг — см. docs.docker.com для установки методом копирования и вставки и расширенных сетевых технологий); а также внутренние механизмы оркестрации Kubernetes/Swarm.

Шаблон с открытым исходным кодом для создания баз знаний на основе больших языковых моделей по образцу [«LLM Wiki» Андрея Карпати](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).

Вы предоставляете исходные материалы. Большая языковая модель читает их, пишет структурированные вики-страницы, создает перекрестные ссылки и поддерживает их в актуальном состоянии. Вы никогда не редактируете вики напрямую — вы отбираете источники и задаете вопросы.

## Как это работает

Система состоит из трех уровней:

```
raw/              Sources you collect (articles, transcripts, notes, PDFs)
wiki/             LLM-written & maintained pages (summaries, concepts, entities, syntheses)
CLAUDE.md         Schema that tells the LLM how to structure everything
```

Рабочий процесс управляется тремя операциями:

| Операция | Триггер | Что происходит |
| --- | --- | --- |
| **Инжект** | "ingest raw/my-source.txt" | LLM считывает исходный файл, создает сводную страницу, создает/обновляет страницы с понятиями и сущностями, добавляет перекрестные ссылки, обновляет индекс и журнал |
| **Запрос** | Задайте любой вопрос | LLM выполняет поиск в вики, синтезирует ответ с цитатами, при необходимости создает синтетическую страницу для новых идей |
| **Lint** | "lint" или "проверка работоспособности" | LLM проверяет все страницы на наличие «сиротских» элементов, противоречий, отсутствующих ссылок, неполных разделов и утверждений с низким уровнем достоверности — исправляет то, что может, и сообщает об остальном |

## Быстрый старт

1. **Клонируйте этот репозиторий**
	```bash
	git clone https://github.com/YOUR_USERNAME/llm-wiki.git my-knowledge-base
	cd my-knowledge-base
	```
2. **Настройте CLAUDE.md** для своего домена
	- Измените раздел «Цель» в соответствии с вашей темой
		- Замените таксономию тегов-заполнителей на собственные категории
		- При необходимости скорректируйте описания уровней достоверности
		- Все остальное (рабочие процессы, форматы страниц, правила создания ссылок) работает как есть
3. **Добавляйте источники в `raw/`**
	- текстовые файлы, расшифровки, статьи, заметки — любой обычный текст
		- после добавления они становятся неизменяемыми; LLM никогда их не редактирует
4. **Укажите LLM, что нужно сделать**
	```
	ingest raw/my-first-source.txt
	```
	LLM создаст сводные страницы, страницы с описанием концепций, страницы с описанием сущностей, перекрестные ссылки и обновит индекс.
5. **Задавайте вопросы**
	```
	What are the key differences between X and Y?
	```
	LLM отвечает на вопросы из вики, ссылаясь на конкретные страницы.
6. **Запускайте проверку работоспособности**
	```
	lint
	```
	LLM проверяет вики и устраняет проблемы.

## Структура каталогов

```
.
├── CLAUDE.md                      # Schema — the LLM's instructions
├── raw/                           # Your source documents (immutable)
└── wiki/
    ├── index.md                   # Master catalog of all pages
    ├── log.md                     # Append-only activity log
    ├── dashboard.md               # Dataview dashboard (Obsidian)
    ├── analytics.md               # Charts View analytics (Obsidian)
    ├── flashcards.md              # Spaced repetition cards
    ├── summaries/                 # One page per source document
    ├── concepts/                  # Concept and framework pages
    ├── entities/                  # People, tools, organizations, etc.
    ├── syntheses/                 # Cross-cutting analyses and comparisons
    ├── journal/                   # Research/session journal entries
    │   └── template.md            # Journal entry template
    └── presentations/             # Marp slide decks
```

## Улучшения

Этот шаблон включает в себя несколько дополнительных элементов, выходящих за рамки основного шаблона вики:

### Панель управления Dataview (wiki/dashboard.md)

Оперативные запросы, которые отображают страницы с низким уровнем достоверности, последние обновления, понятия по тегам и страницы с наибольшим количеством источников. Требуется плагин [Dataview](https://github.com/blacksmithgu/obsidian-dataview) для Obsidian.

### Аналитика в режиме просмотра графиков (wiki/analytics.md)

Визуальная аналитика с круговыми и гистограммами, а также облаками тегов. Требуется плагин [Charts View](https://github.com/caronchen/obsidian-chartsview-plugin) для Obsidian.

### Диаграммы Mermaid

Используйте блоки кода Mermaid на любой вики-странице для создания блок-схем, диаграмм последовательности или концептуальных карт. Встроенная поддержка в Obsidian и GitHub.

### Marp Slides (wiki/presentations/)

Создавайте презентации из Markdown с помощью [Marp](https://marp.app/). Перетаскивайте файлы презентаций в этот каталог.

### Research Journal (wiki/journal/)

Отслеживайте свои исследовательские сессии, эксперименты или прикладную работу с помощью прилагаемого шаблона. При ответе на запросы LLM может ссылаться на записи в журнале.

### Пространственное повторение (wiki/flashcards.md)

Флэш-карточки в формате, используемом плагином [Spaced Repetition](https://github.com/st3v3nmw/obsidian-spaced-repetition) для Obsidian. Попросите LLM сгенерировать флэш-карточки на основе любой вики-страницы.

### MCP-сервер

Это репозиторий работает с возможностями MCP-сервера Claude Code. Укажите MCP-совместимый клиент на этот репозиторий, и LLM сможет программно читать и записывать вики-страницу.

## Настройка под ваш домен

Схема в `CLAUDE.md` не зависит от домена. Чтобы адаптировать ее:

1. **Цель** — опишите свою область знаний в одном абзаце
2. **Таксономия тегов** — замените категории-заполнители на свои собственные (например, для базы знаний по кулинарии: `cuisine`, `technique`, `ingredient`, `equipment`)
3. **Уровни достоверности** — скорректируйте описания в соответствии со стандартами доказательной базы в вашей области
4. **Типы сущностей** — обновите описание страницы сущности в соответствии с тем, что подразумевается под сущностями в вашей области (люди, инструменты, компании и т. д.)
5. **Шаблон журнала** — настройте `wiki/journal/template.md` в соответствии с вашим рабочим процессом

Все остальное — формат страницы, правила создания ссылок, рабочие процессы, правила — универсально и работает во всех доменах.

## Примеры доменов

Этот шаблон подходит для любой темы, требующей глубоких знаний:

- **Исследовательские заметки** — статьи, эксперименты, методологии
- **Анализ книги** — темы, персонажи, авторские приемы
- **Конкурентный анализ** — компании, продукты, тенденции рынка
- **Конспекты курса** — лекции, материалы для чтения, ключевые понятия
- **Личностное развитие** — фреймворки, привычки, краткие пересказы книг
- **Техническая документация** — API, архитектуры, шаблоны проектирования
- **Глубокое погружение в хобби** — любая тема, которую вы хотите освоить
