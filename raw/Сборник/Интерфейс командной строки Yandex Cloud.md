## CLI и принцип работы с ним

CLI (Command Line Interface) — это интерфейс, который позволяет пользователю взаимодействовать с программным обеспечением с помощью текстовых команд, вводимых в консоль или терминал. В контексте Yandex Cloud утилита CLI (yc) используется для управления облачными ресурсами, автоматизации задач и выполнения действий, которые могли бы занять больше времени в графическом интерфейсе.

Пример 1. Получение информации о виртуальной машине.

BASH

```bash
yc compute instance get --name my-vm
```

Эта команда выводит подробную информацию о виртуальной машине с именем `my-vm`, включая её параметры и статус.

Пример 2. Получение списка доступных зон.

BASH

```bash
yc compute zone list
```

Команда выводит список доступных зон, в которых можно создавать ресурсы.

Пример 3. Создание подсети.

Пример команды, которая создаёт новую подсеть с именем `my-subnet` и диапазоном IP-адресов `192.168.0.0/24` в зоне `ru-central1-a`, привязанную к сети `my-network`:

BASH

```bash
yc vpc subnet create \
  --name my-subnet \
  --zone ru-central1-a \
  --range 192.168.0.0/24 \
  --network-name my-network
```

В этих примерах команды строятся по одинаковой структуре, которую можно представить как `yc <сервис> <ресурс> <действие> <флаги>`, то есть:

- **Сервис** (`compute`, `vpc`) определяет, с каким сервисом работает команда.
- **Ресурс** (`instance`, `zone`, `subnet`) указывает на объект, над которым выполняется действие.
- **Действие** (`get`, `list`, `create`) — операция, которая выполняется над ресурсом.
- **Флаги** (`--name`, `--zone`, `--range`, `--network-name`) — дополнительные настройки и уточнения для действия.

Большинство команд, с которыми вы поработаете, будут с похожей структурой. На каждом этапе ввода команды можно посмотреть доступные варианты с помощью флага `--help`. Например, команда `yc --help` даст вам список доступных сервисов, а `yc compute instance --help` — список возможных действий с виртуальной машиной.

Теперь расскажем, как строить команды с учётом структуры. Представьте, вам нужно посмотреть список доступных ролей в облаке, тогда вы можете рассуждать так:

1️⃣ Роль — это сущность сервиса IAM. Посмотрите, есть ли он в списке `yc --help`:

BASH

```bash
$ yc --help
```

```markdown
Command line interface helps you interact with Yandex Cloud services
Usage:
  yc <group|command>
Groups:
  iam                       Manage Yandex Identity and Access Manager resources
  resource-manager          Manage Yandex Resource Manager resources
  compute                   Manage Yandex Compute Cloud resources
  vpc                       Manage Yandex Virtual Private Cloud resources
<...>
```

Как видно, этот сервис называется `iam` в CLI.

2️⃣ Посмотрите, какие ресурсы доступны внутри сервиса IAM с помощью `yc iam --help`:

BASH

```bash
$yc iam --help
```

```markdown
Manage Yandex Identity and Access Manager resources
Usage:
  yc iam <group|command>
Groups:
  role              Manage roles
  service-account   Manage service accounts
  key               Manage IAM keys
  access-key        Manage service account access keys
  api-key           Manage service account API keys
  user-account      Manage user accounts
  service-control   Manage service access to cloud
  workload-identity Manage workload identity
Commands:
  create-token      Create IAM token and print to STDOUT
  revoke-token      Revoke IAM token
Use "yc help [command]" for more information about a command and global flags.
```

Так как нужны роли, то стоит использовать `role`.

3️⃣ Теперь посмотрите список действий над ресурсом `role`:

BASH

```bash
$ yc iam role --help
```

```markdown
Manage roles
Usage:
  yc iam role <command>
Aliases:
  roles
Commands:
  get         Show information about the specified role
  list        List roles
Use "yc help [command]" for more information about a command and global flags.
```

Доступны только `get` и `list`. В описании команд указано, что `get` используется для получения информации о конкретной роли, а `list` — для получения списка ролей. Нужен список, поэтому выбирайте `list`. Так можно получить готовую команду `yc iam role list` без поиска в документации или поисковике.

## Пример: группировка ВМ по количеству ядер

Один из главных плюсов использования CLI — возможность **автоматизировать и оптимизировать задачи**, которые было бы сложно выполнить через web UI. Представьте, вы проводите аудит облачной инфраструктуры компании, в которой могут быть десятки или даже сотни виртуальных машин. Вам нужно их сгруппировать по количеству ядер и посчитать количество машин в каждой группе, то есть узнать, сколько двухъядерных машин, сколько четырёхъядерных и так далее. В web UI такую задачу не выполнить напрямую, так как он предоставляет базовый набор функций для фильтрации и сортировки данных. В CLI вы можете использовать команды и инструменты обработки вывода, например `jq`, для гибкой работы с данными:

BASH

```bash
yc compute instance list --jq  '.[]|.resources.cores' | sort | uniq -c
```

Изучите команду подробнее:

- `yc compute instance list --format json` — команда получает список виртуальных машин. Здесь используется флаг `--format`, который позволяет указать формат вывода данных, в данном случае JSON.
- `jq -r '.[] | .resources.cores'` извлекает количество ядер из каждой виртуальной машины.
- `sort` сортирует количество ядер.
- `uniq -c` подсчитывает количество машин для каждого уникального значения количества ядер.

Пример вывода:

```markdown
3 2
5 4
2 8
```

Это означает, что в облаке есть три виртуальные машины с двумя ядрами, пять машин с четырьмя ядрами и две машины с восемью ядрами.
