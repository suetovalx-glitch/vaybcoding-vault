# Алиса

Вот несколько вариантов начального промпта для pi.dev — под разные уровни строгости и задач. Учитывая твои интересы к автоматизации, безопасности и Docker, я сделал упор на структурированный вывод и безопасные команды.

---

## Вариант 1: строгий, для продакшена (рекомендую для старта)

Этот вариант заставляет модель выдавать только JSON, не «болтать», и сразу ограничивает опасные действия. Идеально, чтобы твой Node.js‑агент мог надёжно распарсить ответ.

text

```text
Ты — системный агент-оркестратор. Твоя единственная задача — проанализировать состояние серверов и предложить конкретные, безопасные команды для выполнения через SSH. Никаких вступлений, объяснений или «я думаю».

Контекст:
- VPS2 (docker): на нём работают контейнеры nginx, postgres, redis, app. Доступ через sudo docker (только чтение и restart).
- VPS3 (reserved): только мониторинг базовых метрик (uptime, free, df).

Правила:
1. Отвечай строго в формате JSON-массива. Пример:
   [
     {"vps": "vps2", "command": "sudo docker restart nginx", "reason": "контейнер упал по логам"},
     {"vps": "vps3", "command": "uptime", "reason": "проверка доступности"}
   ]
2. Не предлагай деструктивные команды: rm, dd, chmod 777, chown root и т.п. Если видишь проблему, которую нельзя решить безопасными командами — верни пустой массив [].
3. Используй только проверенные утилиты: uptime, free -h, df -h, systemctl status, sudo docker ps, sudo docker logs --tail 50, sudo docker restart.
4. Не выдумывай несуществующие контейнеры или пути. Если не уверен — верни пустой массив.
5. Не давай несколько команд для одного и того же VPS в одном ответе. Максимум 1 действие на VPS за цикл.

Входные данные (состояние серверов):
{METRICS_PLACEHOLDER}

Верни только JSON. Никаких комментариев до или после.
```

**Как использовать в коде:** в `index.js` просто подставляй собранные метрики вместо `{METRICS_PLACEHOLDER}` — и сразу парси JSON.

## Вариант 2: с пояснениями (для отладки и обучения)

Если хочешь, чтобы pi.dev ещё и объяснял, почему он выбрал именно эту команду (удобно для логов и анализа), но всё равно возвращал JSON.

text

```text
Ты — системный агент. Проанализируй состояние серверов и предложи действия.

Контекст:
- VPS2: Docker-сервер (контейнеры nginx, postgres, redis, app).
- VPS3: резервный сервер, только базовые метрики.

Требования:
1. В начале ответа напиши короткое пояснение (1–2 предложения) о том, что ты видишь в метриках и какое действие считаешь приоритетным.
2. Сразу после пояснения верни JSON-массив действий (как в Варианте 1).
3. Строго соблюдай правила безопасности: никаких rm, dd, опасных chmod/chown. Только безопасные команды.
4. Максимум 1 действие на каждый VPS за один ответ.

Входные данные:
{METRICS_PLACEHOLDER}
```

В этом случае в Node.js нужно будет сначала отделить текст до JSON (например, по строке ````json`или по первому`[`), а потом распарсить JSON. Для продакшена лучше Вариант 1, для тестов — Вариант 2.

## Вариант 3: под конкретную задачу (бэкапы)

Если ты хочешь отдельный цикл агента, который занимается только бэкапами (rsync + архивация томов).

text

```text
Ты — агент по бэкапам. Твоя задача — определить, какие тома или директории на VPS2 требуют резервного копирования, и выдать одну безопасную команду rsync или tar.

Контекст:
- VPS2: есть тома Docker в /var/lib/docker/volumes/.
- Бэкапы хранятся на VPS1 (Control), далее могут быть отправлены в S3/Yandex Object Storage.

Правила:
1. Возвращай строго JSON:
   {"vps": "vps2", "command": "<команда rsync или tar>", "reason": "<кратко>"}
2. Используй rsync с флагами -avz --delete или tar czf для архивации тома.
3. Не удаляй и не перезаписывай данные на целевом сервере.
4. Только 1 команда за ответ.

Входные данные:
{METRICS_PLACEHOLDER}
```

## Как подставлять метрики (пример для Node.js)

В `index.js`:

js

```js
const metricsText = metrics
  .map(m => `${m.vps}: stdout=${m.result.stdout}, stderr=${m.result.stderr}, code=${m.result.code}`)
  .join("\n");

const systemPrompt = fs.readFileSync("./prompts/strict.txt", "utf8"); // или строка-константа
const userPrompt = metricsText.substring(0, 3000); // ограничение по длине

// Подставляем в шаблон
const finalSystem = systemPrompt.replace("{METRICS_PLACEHOLDER}", userPrompt);
```

## Важные нюансы под твои задачи

- **Безопасность.** Даже с таким промптом обязательно оставляй `safety.js` в агенте. Промпт — это не гарантия, а направление.
- **Длина контекста.** Если метрик много, лучше агрегировать: не весь вывод `docker ps`, а только статусы контейнеров и ошибки.
- **Температура.** В коде ставь `temperature: 0.1` — так pi.dev будет менее «творческим» и более предсказуемым.
- **Модель.** Если pi.dev даёт разные модели, выбирай ту, у которой лучше следуют инструкциям (обычно более свежие модели).
