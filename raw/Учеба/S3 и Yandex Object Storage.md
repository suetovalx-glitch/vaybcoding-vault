## S3 и Yandex Object Storage: что это и зачем нужно

### Что такое S3

**S3 (Simple Storage Service)** — это стандарт облачного объектного хранилища, изначально от Amazon (AWS S3). В нём данные хранятся не как «файлы в папках», а как **объекты** с уникальными ключами внутри контейнеров, которые называются **бакетами (buckets)**.

**Ключевые особенности S3:**

- **Масштабируемость**: можно хранить от нескольких файлов до петабайтов.
- **Доступ по API**: всё делается через HTTP‑запросы (PUT, GET, DELETE и т. д.) или SDK/клиенты.
- **Версионирование, политики доступа, lifecycle‑правила** (автоудаление старых объектов, перенос в холодное хранилище).
- **Интеграция с CDN**: удобно раздавать статику (картинки, JS/CSS) с минимальной задержкой.

---

### Что такое Yandex Object Storage

**Yandex Object Storage** — это S3‑совместимое хранилище в Yandex Cloud. То есть оно реализует тот же самый API, что и AWS S3, но работает в инфраструктуре Яндекса.

Это значит: если твой код/скрипт умеет работать с AWS S3 (через `aws cli`, boto3, minio-client, rclone и т. п.), его можно почти без изменений подключить к Yandex Object Storage — нужно только поменять endpoint и ключи.

---

## Как это выглядит на практике

- **Бакет** — это как «корневая папка» хранилища. Внутри него нет настоящих папок: структура «папок» делается через префиксы в имени объекта. Например, объект с ключом `images/2024/photo.jpg` визуально выглядит как файл `photo.jpg` в папке `2024` внутри `images`.
- **Объект** — это сам файл плюс его метаданные (тип, дата, кастомные теги и т. д.).
- **Доступ** управляется через IAM‑роли и статические ключи (Access Key / Secret Key), либо через instance‑метаданные, если работаешь из облака.

---

## Чем это полезно именно для твоих задач (VPS, бэкапы, автоматизация)

Учитывая, что ты делал скрипты для бэкапов, синхронизации и работал с VPS, вот где Yandex Object Storage особенно удобно:

1. **Надёжное хранение бэкапов сайта** (файлов + дампов БД). Бэкап лежит отдельно от VPS: если сервер «упадёт», бэкап сохранится.
2. **Дешевле и удобнее, чем держать большой диск на VPS**. Платишь только за объём и запросы, а не за целый диск.
3. **Легко автоматизировать** через CLI (`awscli`/`rclone`) или скрипты (Python boto3, Node.js SDK и т. п.).
4. **Можно раздавать статику напрямую из бакета** (например, медиафайлы для блога на WordPress), подключив CDN.

## Как работать с Yandex Object Storage (практические варианты)

### Через `awscli` (самый простой способ, если уже знаком с S3)

Настраиваешь профиль:

bash

```bash
aws configure --profile yandex
```

Вводишь:

- Access Key ID
- Secret Access Key
- Default region: `ru-central1`
- Default output format: `json`

И указываешь endpoint в командах или в конфиге:

bash

```bash
aws s3 ls --endpoint-url=https://storage.yandexcloud.net --profile yandex
aws s3 cp local_file.tar.gz s3://my-backup-bucket/backups/site.tar.gz --endpoint-url=https://storage.yandexcloud.net --profile yandex
```

### Через `rclone` (удобно для регулярных бэкапов)

`rclone` умеет работать с S3‑хранилищами и отлично подходит для автоматизации. Пример настройки (в `rclone.conf`):

ini

```ini
[yandex]
type = s3
provider = Yandex
env_auth = false
access_key_id = YOUR_ACCESS_KEY
secret_access_key = YOUR_SECRET_KEY
region = ru-central1
endpoint = https://storage.yandexcloud.net
```

Потом команды:

bash

```bash
rclone sync /var/www/html yandex:my-backup-bucket/www/
rclone copy /backups/db/all.sql yandex:my-backup-bucket/db/
```

Это очень хорошо ложится на твои скрипты и cron.

### Через Python (если пишешь свои утилиты)

python

```python
import boto3

s3 = boto3.client(
    's3',
    endpoint_url='https://storage.yandexcloud.net',
    aws_access_key_id='YOUR_ACCESS_KEY',
    aws_secret_access_key='YOUR_SECRET_KEY',
    region_name='ru-central1'
)

s3.upload_file('/var/www/html/index.html', 'my-backup-bucket', 'www/index.html')
```

## Важные нюансы

- **Не храни ключи прямо в скриптах**. Используй переменные окружения или файлы с правами `600`.
- **Разделяй права**: создавай отдельный сервисный аккаунт с ролью `storage.editor` только для бакета бэкапов — не используй свои личные ключи.
- **Учитывай стоимость**: платишь за объём хранения, количество запросов и исходящий трафик. Для бэкапов это обычно недорого, но трафик на скачивание может быстро расти.
- **Шифрование**: данные шифруются на стороне сервера (по умолчанию), а при передаче — через HTTPS.
