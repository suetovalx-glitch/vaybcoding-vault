## Что такое API

**API** (Application Programming Interface, «программный интерфейс приложения») — это набор правил и способов, по которым разные программы могут «общаться» друг с другом.

Простыми словами: API — это как меню в ресторане. Вы не готовите блюдо сами, а выбираете его из меню, официант передаёт заказ на кухню, а потом вам приносят готовое. В IT роль «меню» играет API, «официанта» — запрос от вашей программы, а «кухни» — сервер или библиотека, которая выполняет задачу и возвращает результат.

---

## Как работает API

Типичный цикл взаимодействия:

1. **Клиент (ваша программа) отправляет запрос** к API: указывает, что нужно сделать, и передаёт параметры (например, «дай прогноз погоды для Москвы»).
2. **API проверяет запрос**: смотрит, есть ли у вас право на доступ (по ключу/токену), корректны ли данные.
3. **Сервер обрабатывает запрос**: обращается к базе данных, делает вычисления, вызывает другие сервисы.
4. **API возвращает ответ** в заранее определённом формате (чаще всего JSON, реже XML).
5. **Ваша программа использует полученные данные** (показывает пользователю, сохраняет в БД и т. д.).

Пример из жизни: когда на сайте или в приложении отображаются карты или прогноз погоды, скорее всего, используется API стороннего сервиса (Яндекс Карты, OpenWeather и т. п.).

---

## Основные понятия

- **Эндпоинт (endpoint)** — URL, по которому обращаются к конкретной функции API. Например: `https://api.example.com/v1/weather`.
- **HTTP-методы** — глаголы, которые говорят, что вы хотите сделать:
    - `GET` — получить данные;
    - `POST` — создать ресурс (отправить данные);
    - `PUT/PATCH` — обновить;
    - `DELETE` — удалить.
- **Параметры запроса** — дополнительные данные: query-параметры в URL (`?city=Moscow`) или тело запроса (JSON).
- **API-ключ / токен** — способ авторизации, чтобы сервис понимал, кто делает запрос и сколько ему можно вызывать API.
- **Коды состояния HTTP** — сигналы о результате:
    - `200 OK` — всё хорошо;
    - `400 Bad Request` — ошибка в запросе;
    - `401 Unauthorized` — нет доступа;
    - `404 Not Found` — ресурс не найден;
    - `500 Internal Server Error` — ошибка на стороне сервера.

---

## Типы API (самые распространённые)

- **REST API** — самый популярный вариант для веба. Работает через HTTP, данные обычно в JSON, использует стандартные методы (GET, POST и т. д.). Подходит для большинства задач.
- **GraphQL** — позволяет запрашивать ровно те поля, которые нужны, и делать сложные выборки за один запрос. Удобно, когда клиент хочет гибко управлять данными.
- **SOAP** — более строгий и сложный протокол, часто используется в корпоративных системах, передаёт данные в XML.
- **gRPC** — высокопроизводительный протокол для микросервисов, использует бинарный формат и HTTP/2.

## Как работать с API: пошаговый план

1. **Найдите документацию API**. Это главный источник: там описаны эндпоинты, параметры, примеры запросов и ответов, правила авторизации.
    
2. **Получите доступ**. Зарегистрируйтесь в сервисе, создайте приложение/проект, получите API‑ключ или настройте OAuth‑токены.
    
3. **Протестируйте запросы вне кода**. Используйте инструменты:
    
    - **Postman** или **Insomnia** — удобные GUI‑клиенты для отправки запросов и просмотра ответов.
    - **curl** — для быстрых тестов из терминала.
    
    Пример curl-запроса:
    
    bash
    
    ```bash
    curl -H "Authorization: Bearer ВАШ_ТОКЕН" \
         "https://api.example.com/v1/items?limit=10"
    ```
    
4. **Напишите код на нужном языке**. Примеры:
    
    - **JavaScript (Node.js)**:
        
        js
        
        ```js
        const res = await fetch('https://api.example.com/v1/items', {
          headers: { 'Authorization': 'Bearer ВАШ_ТОКЕН' }
        });
        const data = await res.json();
        ```
        
    - **Python**:
        
        python
        
        ```python
        import requests
        
        r = requests.get(
            "https://api.example.com/v1/items",
            headers={"Authorization": "Bearer ВАШ_ТОКЕН"},
            params={"limit": 10}
        )
        data = r.json()
        ```
        
5. **Обработайте ошибки и лимиты**. Учитывайте коды ошибок, таймауты, лимиты количества запросов (rate limits) и делайте повторные попытки (retry) при временных сбоях.
    
6. **Обеспечьте безопасность**. Не храните API‑ключи в коде, используйте переменные окружения; передавайте данные только по HTTPS; не публикуйте ключи в репозиториях.

## Практические примеры, близкие к вашим прошлым задачам

Учитывая ваши интересы (VPS, автоматизация, Docker, Obsidian и т. п.), API часто используют так:

- **Автоматизация метрик на VPS**: скрипты на Python/Node.js запрашивают данные у API мониторинговых систем (Prometheus, Netdata) и сохраняют или визуализируют их.
- **Интеграция с сервисами**: например, отправлять уведомления в Telegram через API бота, получать данные из Zotero/Obsidian через плагины или внешние API.
- **Docker и оркестрация**: API Docker Engine (через сокет или HTTP) позволяет программно управлять контейнерами, что удобно для CI/CD и собственных панелей управления.
- **ИИ‑ассистенты и агенты**: многие ИИ‑сервисы предоставляют API (OpenAI, Anthropic и др.), чтобы вызывать их из своих скриптов, встраивать в ботов или агенты.

---

## Полезные инструменты

- **Postman / Insomnia** — для тестирования API.
- **curl / httpie** — для быстрых запросов из терминала.
- **Swagger / OpenAPI** — стандарты описания API и автодокументации.
- **SDK** (Software Development Kit) — готовые библиотеки от провайдера API, чтобы не писать низкоуровневые запросы вручную.

---

## Частые ошибки новичков

- Отправляют запросы без заголовков авторизации или с неверным форматом токена.
- Не проверяют коды состояния и пытаются сразу парсить JSON даже при ошибке сервера.
- Жёстко прописывают API‑ключи прямо в коде и коммитят их в Git.
- Игнорируют лимиты запросов и получают блокировки.
- Не учитывают различия между тестовой и продакшн‑версией API (разные URL, лимиты, форматы).
