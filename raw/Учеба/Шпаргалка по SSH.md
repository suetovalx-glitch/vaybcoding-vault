## Шпаргалка по SSH

---

## Базовые команды для подключения

- `ssh user@host` — подключиться к серверу (например, `ssh alice@192.168.1.10`).
- `ssh -p PORT user@host` — подключение на нестандартный порт (по умолчанию — 22).
- `ssh user@host command` — выполнить одну команду на удалённой машине и сразу выйти (например, `ssh alice@server uptime`).

---

## Работа с ключами (аутентификация без пароля)

- `ssh-keygen` — создать пару ключей (по умолчанию в `~/.ssh/id_rsa` и `id_rsa.pub`).
- `ssh-copy-id user@host` — скопировать публичный ключ на сервер (автоматически добавит в `~/.ssh/authorized_keys`).
- Вручную: скопировать содержимое `id_rsa.pub`, вставить в `~/.ssh/authorized_keys` на сервере, права: `chmod 700 ~/.ssh` и `chmod 600 ~/.ssh/authorized_keys`.

**Важно:** приватный ключ (`id_rsa`) никогда не передавайте и не выкладывайте в репозитории.

---

## Передача файлов по SSH

- `scp local_file user@host:remote_path` — загрузить файл на сервер.
- `scp user@host:remote_file local_path` — скачать файл с сервера.
- `scp -r local_dir user@host:remote_dir` — копировать директорию рекурсивно.

Альтернатива с лучшей интерактивностью: `rsync -avz -e ssh source user@host:dest`.

---

## Полезные опции SSH

|Опция|Значение|
|---|---|
|`-p PORT`|Порт SSH на сервере|
|`-i key_file`|Использовать конкретный приватный ключ|
|`-v` / `-vv` / `-vvv`|Режим отладки (подробный вывод для диагностики проблем)|
|`-C`|Включить сжатие (полезно при медленном канале)|
|`-N`|Не выполнять команду (для туннелей)|
|`-f`|Перейти в фон после аутентификации (часто с `-N`)|

---

## Туннели (проброс портов)

- Локальный проброс: `ssh -L LOCAL_PORT:DEST_HOST:DEST_PORT user@server`  
    Пример: `ssh -L 8080:localhost:3000 alice@vps` — трафик на `localhost:8080` пойдёт на `vps:3000`.
- Удаленный проброс: `ssh -R REMOTE_PORT:LOCAL_HOST:LOCAL_PORT user@server`.
- Динамический SOCKS-прокси: `ssh -D LOCAL_PORT user@server`, затем в браузере указать прокси `SOCKS5 localhost LOCAL_PORT`.

## Конфигурация (`~/.ssh/config`)

Удобно задать алиасы и настройки для частых подключений:

text

```text
Host myvps
  HostName 192.168.1.10
  User alice
  Port 2222
  IdentityFile ~/.ssh/myvps_key
  ServerAliveInterval 60
  ServerAliveCountMax 3
```

После этого: `ssh myvps`.

`ServerAliveInterval` помогает не терять соединение на нестабильных каналах.

## Безопасность и частые проблемы

- **Порт 22 по умолчанию** — лучше сменить в `/etc/ssh/sshd_config` на другой и перезапустить SSH.
- **Отключить вход по паролю**, оставить только ключи: `PasswordAuthentication no`.
- **Ограничить пользователей**: `AllowUsers alice bob`.
- **Проверить права**: на сервере папка `~/.ssh` должна быть `700`, файл `authorized_keys` — `600`.

Частые ошибки и решения:

- `Permission denied (publickey,password)` — проверить права на ключи и `authorized_keys`, убедиться, что приватный ключ используется (`-i`).
- `Host key verification failed` — сервер сменил ключи (например, после переустановки ОС). Можно удалить строку с хостом из `~/.ssh/known_hosts` или использовать `ssh -o StrictHostKeyChecking=no` (не рекомендуется для продакшена).
- Медленные/падающие соединения — добавить `ServerAliveInterval`, проверить сеть и нагрузку на сервере.

---

## Управление сессиями и горячие клавиши в терминале

- `Ctrl+D` или `exit` — выйти из удалённой сессии.
- `~.` — разорвать SSH-соединение (работает только если SSH в переднем плане).
- `Tab` — автодополнение команд и путей.
- `↑` — предыдущая команда в истории.

---

## Диагностика

- `ssh -v user@host` — подробный вывод, чтобы понять, где происходит сбой.
- На сервере: смотреть логи SSH (зависит от ОС):
    - Debian/Ubuntu: `grep sshd /var/log/auth.log`
    - CentOS/RHEL: `grep sshd /var/log/secure`

Учитывая, что ты работал с VPS, WSL и автоматизацией, вот пара полезных сценариев:

- **Автоматизация проверок метрик** (как в твоём запросе про скрипты): можно запускать команды через SSH без интерактивного входа:  
    `ssh alice@vps "uptime && free -h && df -h"`.
- **WSL + SSH**: в WSL ключи хранятся в `~/.ssh`, и ты можешь использовать их для подключения к VPS напрямую из Windows.
- **Синхронизация и деплой**: `rsync` поверх SSH удобен для синхронизации файлов между локальной машиной (например, в Obsidian) и VPS.
