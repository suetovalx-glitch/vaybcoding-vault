

Podman — инструмент для работы с контейнерами, аналог Docker, но без демона: работает напрямую через rootless‑режим и лучше интегрируется с systemd.

---

## Базовые команды (как быстрый старт)

|Действие|Команда|Комментарий|
|---|---|---|
|Запустить контейнер|`podman run -it <образ>`|`-it` — интерактивный режим с терминалом|
|Посмотреть запущенные контейнеры|`podman ps`|Аналог `docker ps`|
|Посмотреть все контейнеры (в т.ч. остановленные)|`podman ps -a`||
|Остановить контейнер|`podman stop <id/имя>`||
|Удалить контейнер|`podman rm <id/имя>`|Можно несколько ID подряд|
|Список образов|`podman images`||
|Скачать образ|`podman pull <образ>`||
|Удалить образ|`podman rmi <id/образ>`||

---

## Работа с именами и алиасами (чтобы не путать с Docker)

- Если у вас стоит и Docker, и Podman, можно сделать алиас:  
    `alias docker=podman` (в `~/.bashrc` или `~/.zshrc`).
- Podman поддерживает те же CLI‑команды, что и Docker, поэтому большинство скриптов «просто работают».

---

## Запуск без root (rootless)

Это ключевое отличие Podman: контейнеры запускаются от имени пользователя.

- Проверка статуса: `podman info` → смотрите секцию `host.security.rootless`.
- Если нужно, включите rootless: обычно в современных дистрибутивах (Fedora, RHEL, CentOS Stream) он уже включён.
- Для systemd‑сервисов есть `podman generate systemd` — генерирует unit‑файлы для автозапуска контейнеров.

---

## Управление томами и сетью

|Задача|Команда / подход|
|---|---|
|Проброс папки хоста в контейнер|`podman run -v /путь/на/хосте:/путь/в/контейнере <образ>`|
|Проброс портов|`podman run -p <порт_хоста>:<порт_контейнера> <образ>`|
|Запуск в фоне (detached)|`podman run -d <образ>`|
|Сеть (по умолчанию bridge)|Работает аналогично Docker; можно создавать сети: `podman network create <имя>`|

## Build (сборка образов)

Podman умеет собирать образы без Docker Daemon.

- Сборка по Dockerfile:  
    `podman build -t myimage:latest .`
- Можно использовать Buildah (часто идёт вместе с Podman) для более сложных сценариев.
- Push/pull в реестры: `podman push`, `podman pull`.

---

## Podman Compose (аналог docker-compose)

Если нужен compose‑файл:

1. Установите: `sudo dnf install podman-docker` или аналог для вашего дистрибутива.
2. Запустите: `podman compose -f docker-compose.yml up -d`.
3. Остановить/удалить: `podman compose down`.

> Примечание: `podman compose` использует тот же формат `docker-compose.yml`, поэтому старые файлы подходят без изменений.

---

## Полезные команды для диагностики

- Логи контейнера: `podman logs <id/имя>`.
- Инспектировать контейнер: `podman inspect <id/имя>` (JSON с деталями).
- Посмотреть процессы внутри контейнера: `podman top <id/имя>`.
- Статистика по ресурсам: `podman stats`.

---

## Частые отличия от Docker (на что обратить внимание)

- **Нет демона**: Podman не требует `systemctl start docker`.
- **Rootless по умолчанию**: безопаснее и проще для пользователей.
- **systemd‑интеграция**: `podman generate systemd` даёт нативные unit‑файлы.
- **Pod/группы контейнеров**: Podman умеет создавать «pods» (группы контейнеров с общей сетью/томами), как в Kubernetes.  
    Пример: `podman pod create --name mypod`, затем контейнеры добавляются в pod через `--pod mypod`.

## Мини‑пример: быстрый веб‑сервер

bash

```bash
# Скачиваем образ
podman pull nginx

# Запускаем с пробросом порта и тома
podman run -d -p 8080:80 -v ./html:/usr/share/nginx/html --name web nginx

# Проверяем
curl http://localhost:8080

# Логи
podman logs web

# Остановить и удалить
podman stop web
podman rm web
```

## Практические советы (особенно если вы работаете на VPS)

- Используйте rootless: это снижает риски и упрощает управление правами.
- Храните образы и контейнеры в домашней директории пользователя: `/home/<user>/.local/share/containers`.
- Для автоматизации и автозапуска используйте `podman generate systemd`, а не ручные скрипты.
- Если нужна оркестрация (кластер, автоскейл), рассмотрите Kubernetes/OKD; Podman хорош как локальный/VPS‑инструмент и как «низкоуровневый» рантайм.

Если скажете, под какой сценарий вам нужна шпаргалка (например, «для CI/CD», «для VPS с Nginx/PHP», «для разработки микросервисов»), могу сделать более узкую версию с готовыми сниппетами.
