## Шпаргалка по Docker

Учитывая твой интерес к работе на VPS и автоматизации, сделала упор на команды, которые реально пригодятся в реальных сценариях (в том числе для CI/CD, деплоя и диагностики).

---

## Базовые понятия

- **Образ (image)** — шаблон только для чтения: код + зависимости + настройки. Аналог «установочного файла».
- **Контейнер (container)** — запущенный экземпляр образа с собственным состоянием. Изолированная среда.
- **Dockerfile** — файл с инструкциями для сборки образа.
- **Volume (том)** — способ хранить данные вне контейнера (чтобы не пропали при удалении).
- **Network (сеть Docker)** — изолированная сеть, где контейнеры могут общаться по имени.
- **Registry** — хранилище образов (самый популярный публичный — Docker Hub).

## Самые частые команды (с полезными флагами)

|Команда|Что делает|Полезные флаги|
|---|---|---|
|`docker ps`|Показать запущенные контейнеры|`-a` — все (включая остановленные), `-q` — только ID|
|`docker pull`|Скачать образ из реестра|`--platform linux/amd64` (если нужна конкретная платформа)|
|`docker run`|Создать и запустить контейнер|`-d` — фон, `-p HOST:CONTAINER` — проброс портов, `-v HOST_PATH:CONTAINER_PATH` — том, `--name` — имя, `--rm` — удалить после остановки, `-e VAR=value` — переменные окружения|
|`docker stop`|Корректно остановить контейнер (SIGTERM)|`--time=10` (время на завершение)|
|`docker kill`|Принудительно остановить (SIGKILL)|—|
|`docker rm`|Удалить остановленный контейнер|`-f` — принудительно (остановить и удалить)|
|`docker logs`|Посмотреть логи контейнера|`-f` — в реальном времени, `--tail 50` — последние N строк|
|`docker exec`|Выполнить команду в работающем контейнере|`-it` — интерактивный терминал (например, `bash`)|
|`docker images`|Список образов|`-a` — все, включая промежуточные слои|
|`docker rmi`|Удалить образ|`-f` — принудительно|
|`docker build`|Собрать образ из Dockerfile|`-t name:tag` — задать имя и тег, `--no-cache` — не использовать кэш (полезно при отладке)|
|`docker system prune`|Очистить неиспользуемые ресурсы|`-a` — удалить также образы без контейнеров, `--volumes` — осторожно: удалит и неиспользуемые тома|

## Частые сценарии и готовые примеры

### Быстрый запуск с пробросом порта и томом

bash

```bash
docker run -d -p 8080:80 -v ./data:/var/www/html --name my-web nginx
```

- `-d`: в фоне.
- `-p 8080:80`: на хосте порт 8080 → внутри контейнера 80.
- `-v`: папка `./data` на хосте монтируется в `/var/www/html` в контейнере (данные сохраняются).

### Зайти внутрь работающего контейнера

bash

```bash
docker exec -it my-web bash
```

### Посмотреть, сколько ресурсов ест контейнер

bash

```bash
docker stats
```

(удобно на VPS для быстрой диагностики нагрузки).

### Собрать свой образ

В папке с `Dockerfile`:

bash

```bash
docker build -t my-app:1.0 .
```

Точка в конце — это «контекст сборки» (текущая директория).

## Dockerfile: самые важные инструкции

- `FROM` — базовый образ (например, `FROM node:20-alpine`).
- `WORKDIR` — рабочая директория внутри контейнера.
- `COPY` — скопировать файлы из хоста в образ.
- `RUN` — выполнить команду при сборке (установка пакетов и т.п.).
- `ENV` — задать переменные окружения.
- `EXPOSE` — объявить порт (справочно, не пробрасывает сам по себе).
- `CMD` — команда по умолчанию при запуске контейнера.

**Пример минимального Dockerfile для Node.js:**

dockerfile

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
```

## Docker Compose (для мультиконтейнерных приложений)

Файл `docker-compose.yml` описывает несколько контейнеров и их связи.

**Минимальный пример:**

yaml

```yaml
version: "3.9"
services:
  web:
    build: .
    ports:
      - "8080:80"
    volumes:
      - ./data:/var/www/html
    environment:
      - NODE_ENV=production
  db:
    image: postgres:15
    environment:
      POSTGRES_PASSWORD: example
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

**Команды:**

- `docker compose up -d` — запустить в фоне.
- `docker compose down` — остановить и удалить контейнеры (тома по умолчанию остаются).
- `docker compose logs -f` — логи всех сервисов в реальном времени.
- `docker compose exec web bash` — зайти в конкретный сервис.

## Практические советы под твой стек (VPS, автоматизация, скрипты)

- **На VPS всегда используй `-d` и `--restart unless-stopped` или `always`** — чтобы сервисы поднимались после перезагрузки. Пример:
    
    bash
    
    ```bash
    docker run -d --restart unless-stopped -p 8080:80 nginx
    ```
    
    Или в compose: `restart: unless-stopped`.
- **Не храни данные в контейнере.** Всегда используй volumes или bind-mounts (`-v`). Иначе при `docker rm` данные пропадут.
- **Для отладки на VPS:** `docker ps`, `docker logs -f`, `docker stats`, затем `docker exec -it` для проверки изнутри.
- **Если нужно быстро освободить место на VPS:**
    
    bash
    
    ```bash
    docker system prune -a
    ```
    
    Но сначала проверь, что не удалишь нужные тома и образы.
- **Обращай внимание на теги образов.** Не используй `latest` в продакшене: он нестабилен. Лучше `nginx:1.27` или конкретный SHA.

## Частые ошибки и как их избегать

- **«Порт уже занят»**: проверь, не слушает ли что-то на этом порту (`ss -tlnp` или `netstat`), либо выбери другой порт на хосте.
- **«Permission denied» при работе с Docker**: на большинстве VPS нужно либо добавить пользователя в группу `docker` (`sudo usermod -aG docker $USER`), либо использовать `sudo` перед командами.
- **Путаница между `stop` и `kill`**: в продакшене используй `stop`, чтобы приложение успело корректно завершить работу (закрыть соединения, сбросить кэш). `kill` — только если контейнер завис.
- **Данные исчезают после перезапуска**: значит, ты не используешь volumes. Добавь `-v` или настрой в compose.

## Связь с твоими прошлыми задачами

- Для **автоматизации проверки метрик на VPS** удобно запускать лёгкие контейнеры с экспортерами (node_exporter, redis_exporter и т.д.) через compose и собирать метрики в Netdata/Prometheus.
- Для **работы с Node.js на VPS** — используй образы на базе `alpine` или slim-версий, чтобы уменьшить размер и поверхность атаки.
- Для **скриптов и синхронизации** (Obsidian, Syncthing и т.п.) — лучше запускать их отдельными контейнерами с volume, чтобы данные были на хосте и их можно было бэкапить.

Если скажешь, под какую задачу тебе нужна шпаргалка (например, «для деплоя Node.js-приложения на VPS» или «для локальной разработки с несколькими сервисами»), могу дать готовый compose-файл и пошаговый план запуска.
