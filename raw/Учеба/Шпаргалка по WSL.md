## Шпаргалка по WSL (Windows Subsystem for Linux)

WSL — подсистема Linux в Windows, позволяет запускать полноценное Linux‑окружение (включая CLI, пакеты, скрипты) прямо в Windows. Особенно полезно для DevOps, разработки и работы с контейнерами (в связке с Podman/Docker).

---

## Базовые команды управления WSL

|Задача|Команда|Комментарий|
|---|---|---|
|Список установленных дистрибутивов|`wsl --list` или `wsl -l`|Показывает все дистрибутивы и их состояние|
|Показать только запущенные|`wsl --status`|Или `wsl -l -v` для статуса (running/stopped)|
|Запустить дистрибутив|`wsl -d <имя>`|Например: `wsl -d Ubuntu`|
|Завершить все дистрибутивы|`wsl --shutdown`|Полезно, если WSL «зависает» или порты не освобождаются|
|Экспорт дистрибутива|`wsl --export <имя> <путь/к/архиву.tar>`|Резервная копия окружения|
|Импорт дистрибутива из архива|`wsl --import <имя> <папка> <архив.tar>`|Восстановление или перенос на другой ПК|
|Удалить дистрибутив|`wsl --unregister <имя>`|**Внимание:** удаляет все данные дистрибутива безвозвратно|

## Установка WSL и дистрибутива

1. **Включить WSL** (если ещё не включён):
    
    powershell
    
    ```powershell
    wsl --install
    ```
    
    Эта команда включает WSL, ставит ядро WSL2 и по умолчанию ставит Ubuntu.
    
2. **Установить конкретный дистрибутив из Microsoft Store** либо через:
    
    powershell
    
    ```powershell
    wsl --install -d <ИмяДистрибутива>
    ```
    
    Примеры: `Ubuntu`, `Debian`, `Kali-linux`.
    
3. **Проверить версию WSL** (1 или 2):
    
    powershell
    
    ```powershell
    wsl --version
    ```
    
    Если не показывает версию — обновите компонент через `wsl --update`.
    
4. **Перевести дистрибутив на WSL2** (рекомендуется):
    
    powershell
    
    ```powershell
    wsl --set-version <имя> 2
    ```
    
    Пример: `wsl --set-version Ubuntu 2`.
    
5. **Задать дистрибутив по умолчанию**:
    
    powershell
    
    ```powershell
    wsl --set-default <имя>
    ```

## Работа внутри WSL: файлы и пути

- **Доступ к файлам Windows из WSL**: смонтированы в `/mnt/c`, `/mnt/d` и т.д.  
    Пример: `/mnt/c/Users/username/Projects`.
- **Доступ из Windows к файлам WSL**: через `\\wsl$\<имя_дистрибутива>\`.  
    Например: `\\wsl$\Ubuntu\home\username`.
- **Рекомендуемый подход**: проекты держать **внутри WSL** (не на `/mnt/...`), чтобы избежать проблем с производительностью и совместимостью файловых систем.

## Настройка окружения (полезно для разработки и VPS‑задач)

- Установить базовые утилиты (на примере Ubuntu):
    
    bash
    
    ```bash
    sudo apt update && sudo apt install -y curl git vim htop net-tools build-essential
    ```
    
- Настроить SSH (если нужно подключаться к WSL как к «мини‑VPS»):
    1. `sudo apt install -y openssh-server`
    2. Отредактировать `/etc/ssh/sshd_config`: разрешить `PasswordAuthentication yes` (или использовать ключи).
    3. `sudo service ssh start`
- Для работы с контейнерами: в WSL2 можно ставить Podman (без Docker Daemon) или Docker Desktop с интеграцией WSL.

## Частые проблемы и решения

|Проблема|Решение|
|---|---|
|WSL не запускается, ошибка 0x80070057 или похожая|Выполнить `wsl --shutdown`, затем попробовать снова|
|Медленная работа при чтении файлов на `/mnt/c`|Перенести проект внутрь WSL (`/home/username/project`)|
|Не освобождаются порты после остановки WSL|`wsl --shutdown` решает проблему|
|Нет графического интерфейса (GUI)|Для GUI в WSL2 нужен Windows 11 + WSLg (уже включено по умолчанию) либо X‑сервер на Windows|

## Полезные сниппеты (для автоматизации и быстрой настройки)

**Создать удобную точку входа в WSL из PowerShell/CMD:**

powershell

```powershell
wsl -d Ubuntu
```

**Быстрый скрипт инициализации (один раз):**

bash

```bash
sudo apt update
sudo apt install -y git curl vim htop
curl -fsSL https://get.docker.com -o get-docker.sh && sh get-docker.sh  # если нужен Docker
# или для Podman: sudo apt install -y podman
```

**Посмотреть использование ресурсов (аналог top, но на уровне WSL):**  
В Windows PowerShell:

powershell

```powershell
Get-Process -Name "WslHost"
```

Внутри WSL: `htop` (после установки).

## Интеграция с инструментами разработки (VS Code, Git, CLI)

- **VS Code**: расширение «Remote — WSL» позволяет открывать папку внутри WSL как рабочее пространство. Это даёт нативный Linux‑стек в редакторе.
- **Git**: можно использовать Git внутри WSL или из Windows — но лучше держать репозитории внутри WSL, чтобы избежать различий в правах и окончаниях строк.
- **CLI‑инструменты** (Homebrew, nvm, pyenv и т.п.) удобно ставить внутри WSL. Например, Homebrew в Linux работает отдельно от Windows‑версии.

## Отличия WSL1 vs WSL2 (кратко)

|Параметр|WSL1|WSL2|
|---|---|---|
|Файловая система|Проброс NTFS (быстрый доступ к дискам Windows)|Виртуальная ext4 (лучше совместимость с Linux)|
|Совместимость системных вызовов|Частичная|Полная (почти как настоящий Linux)|
|Производительность I/O в Linux‑папках|Ниже|Выше|
|Сетевой стек|Общий с Windows|Отдельный (IP может меняться при перезапуске)|
|**Рекомендация**|Только если нужна максимальная скорость доступа к файлам на Windows|Почти всегда лучше WSL2 для разработки и контейнеров|

## Мини‑пример: быстрый старт для разработки (Node/Python/Go)

bash

```bash
# Внутри WSL
sudo apt update
sudo apt install -y nodejs npm python3 python3-pip golang

# Проверить версии
node -v && npm -v && python3 -v && go version

# Создать тестовый проект
mkdir myproject && cd myproject
echo "console.log('Hello from WSL')" > index.js
node index.js
```
