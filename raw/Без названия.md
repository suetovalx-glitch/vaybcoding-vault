**Вот общещанный гайд по подключени**ю **Hermes-агента к Hermes Desktop (через SSH-туннель)**  
  
  
Логика: **сервер → Hermes → dashboard с basic auth → SSH-туннель → Desktop на `127.0.0.1:9120`**  
  
---  
  
## Шаг 1. Заходим на сервер (в терминале на своём компе)  
  

ssh root@ВАШ_IP_СЕРВЕРА

  
  
- На вопрос про fingerprint → пишем `yes`  
- Вводим пароль сервера (его дал хостинг)  
- При первом входе сервер попросит сменить пароль: `Новый пароль` → повтор. Соединение закроется.  
  
Заходим снова, уже с новым паролем:  
  

ssh root@ВАШ_IP_СЕРВЕРА

  
  
---  
  
## Шаг 2. Обновляем сервер и ставим нужные утилиты  
  

apt update && apt upgrade -y

  
  

apt install -y curl ca-certificates nano openssl ufw jq

  
  
Эти пакеты (`curl`, `openssl`, `nano`, `ufw`, `jq`) нужны на следующих шагах — ставим сразу, чтобы ничего не отвалилось.  
  
---  
  
## Шаг 3. Ставим Hermes-агента  
  

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

  
  
Чтобы команда `hermes` заработала без перезахода:  
  

source ~/.bashrc 2>/dev/null || true
export PATH="$HOME/.local/bin:$PATH"

  
  
---  
  
## Шаг 4. Настраиваем модель  
  

hermes model

  
  
- Когда попросит `OPENROUTER_API_KEY` — вставляем **свой ключ с openrouter.ai/keys**  
- Выбираем модель (в видео — DeepSeek V4 Flash)  
  
Проверяем, что агент отвечает:  
  

hermes chat -q "Привет, ты работаешь?"

  
  
> ℹ️ После этого шага ключ OpenRouter уже сохранён в `~/.hermes/.env` — **второй раз вручную его добавлять не нужно.**  
  
---  
  
## Шаг 5. Добавляем доступ к dashboard (логин/пароль)  
  
Генерируем случайный секрет (копируем вывод):  
  

openssl rand -base64 32

  
  
Открываем файл секретов:  
  

nano ~/.hermes/.env

  
  
Добавляем в самый низ **только 3 строки** (ключ OpenRouter там уже есть с шага 4):  
  

HERMES_DASHBOARD_BASIC_AUTH_USERNAME=ВАШ_ЛОГИН
HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=ВАШ_ПАРОЛЬ
HERMES_DASHBOARD_BASIC_AUTH_SECRET=СЕКРЕТ_ИЗ_ШАГА_ВЫШЕ

  
  
Сохраняем: **Ctrl+O → Enter**, выходим: **Ctrl+X**  
  
Закрываем файл от чужих глаз:  
  

chmod 600 ~/.hermes/.env

  
  
Проверяем, что всё записалось (значения скрыты):  
  

grep -E "HERMES_DASHBOARD_BASIC_AUTH_USERNAME|HERMES_DASHBOARD_BASIC_AUTH_PASSWORD|HERMES_DASHBOARD_BASIC_AUTH_SECRET" ~/.hermes/.env | sed 's/=.*/=***hidden***/'

  
  
---  
  
## Шаг 6. Закрываем dashboard от интернета (фаервол)  
  

ufw allow OpenSSH
ufw deny 9119/tcp
ufw --force enable
ufw status

  
  
Порт `9119` будет недоступен снаружи — подключаемся к нему только через SSH-туннель.  
  
---  
  
## Шаг 7. Запускаем dashboard (только локально на сервере)  
  

hermes dashboard --no-open --host 127.0.0.1 --port 9119

  
  
🔒 `--host 127.0.0.1` означает «слушать только сам сервер» — снаружи dashboard физически недоступен, наружу он выходит **только через SSH-туннель**. (Фаервол из шага 6 — дополнительная подстраховка.)  
  
⚠️ **Это окно терминала не закрывать** — пока оно открыто, dashboard работает. Закроешь окно — dashboard остановится.  
  
---  
  
## Шаг 8. Поднимаем SSH-туннель (в НОВОМ окне терминала на своём компе)  
  

ssh -N -L 9120:127.0.0.1:9119 root@ВАШ_IP_СЕРВЕРА

  
  
- Вводим пароль сервера, **окно тоже оставляем открытым**.  
- Туннель пробрасывает локальный порт `9120` → dashboard `9119` на сервере.  
  
Проверяем, что туннель и dashboard живы (в **третьем** окне терминала на своём компе):  
  

curl -s http://127.0.0.1:9120/api/status | jq '.auth_required, .auth_providers'

  
  
Ожидаемый ответ:  
  

true
[
  "basic"
]

  
  
Если тут не `basic` — Desktop попросит session token, и вход по логину/паролю не сработает. Значит, что-то с `.env` или dashboard.  
  
---  
  
## Шаг 9. Подключаемся в приложении Hermes Desktop  
  
1. Settings → **Gateway** → выбираем **Remote Gateway**  
2. Remote URL:  
  

http://127.0.0.1:9120

  
  
3. Жмём **Sign in**, вводим `ЛОГИН` и `ПАРОЛЬ` из `.env`  
  
---  
  
## Шаг 10. Проверяем, что Desktop реально работает на сервере  
  
В чате просим агента ответить, если отвечает - значит все работает.  
  
---  
  
📌 Порты `9119` (dashboard на сервере) и `9120` (локальный конец туннеля) — произвольные, можно оставить как есть.
