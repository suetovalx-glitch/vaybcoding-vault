# Prompt pattern: строгий JSON-вывод

## Summary

Базовый паттерн системного промта для продакшн-агента: модель обязана вернуть **только JSON-массив команд** (или пустой массив), без пояснений, без «я думаю», без «вот что я бы сделал». Это позволяет вызывающему коду (Node.js-агенту, оркестратору) надёжно парсить результат и применять команды безопасно.

## Current Understanding

### Когда применять

- Когда LLM используется как «решатель» в автоматизированном контуре (CI/CD, мониторинг, деплой, рутина на сервере).
- Когда нужно, чтобы LLM **не делала ничего сверх** того, что попросили.
- Когда в коде нет места для креатива — есть место для исполнения.

### Базовые правила

1. **Строгий формат выхода** — JSON-массив объектов `{tool, args, reason}` или `{vps, command, reason}` и т. п.
2. **Запрет деструктивных операций** — `rm -rf /`, `dd`, `chmod 777`, `chown root`, `mkfs`, форматирование дисков, отключение фаерволов и т. п. Прямо перечислить в промте.
3. **Whitelist утилит** — только проверенные команды, которые можно вызывать без сюрпризов (`uptime`, `free -h`, `df -h`, `systemctl status`, `sudo docker ps`, `sudo docker logs --tail 50`, `sudo docker restart`).
4. **Лимит действий за цикл** — максимум 1 команда на единицу работы (1 VPS, 1 сервис). Это предотвращает каскадное исполнение.
5. **Если проблему нельзя решить безопасной командой — возвращать пустой массив**, а не выдумывать решение.
6. **Не выдумывать несуществующие сущности** (контейнеры, пути, пользователи). Если данных не хватает — пустой массив.
7. **Никаких вступлений и заключений** в ответе модели.

### Почему это работает

- Снижает площадь атаки: модель не может «убедить себя» выполнить опасное действие через контекст.
- Делает интеграцию с backend-кодом тривиальной (`JSON.parse(...)`).
- Делает поведение воспроизводимым: один и тот же вход → один и тот же выход (статистически).

### Известные ограничения

- **Prompt-injection через содержимое логов** — если модель читает `docker logs --tail 50` и потом действует на основе прочитанного, злоумышленник может положить вредоносную инструкцию в логи. Решения: парсить структурированные логи, не передавать свободный текст обратно в LLM без фильтрации.
- **Снижение гибкости** — слишком жёсткий промт не даёт агенту «думать» и адаптироваться к нестандартным ситуациям. Решение: разные уровни строгости под разные задачи (прод / тест / эксперимент).
- **Не панацея** — JSON-формат не защищает от опасного действия, если в whitelist попало что-то вроде `bash -c "..."`.

## Минимальный шаблон

```text
Ты — системный агент-оркестратор. Твоя единственная задача —
проанализировать состояние и предложить конкретные безопасные команды.
Никаких вступлений, объяснений или "я думаю".

Правила:
1. Отвечай строго в формате JSON-массива.
2. Не предлагай деструктивные команды.
3. Используй только проверенные утилиты: <whitelist>.
4. Не выдумывай несуществующие сущности.
5. Не давай несколько команд для одной единицы работы в одном ответе.
6. Если проблему нельзя решить безопасной командой — верни [].

Входные данные: <STATE_JSON>
```

## Contradictions / Uncertainty

- В новых моделях (Claude 4, GPT-5) JSON-стрикт может быть слишком жёстким, потому что они хорошо «понимают» контекст. Возможно, стоит ослаблять промт для исследовательских задач.
