# Память и навыки агента

## Summary

Концепция «памяти» и «навыков» в современных LLM-агентах — это **не fine-tuning**, а внешние файлы с подсказками и инструкциями, к которым агент обращается в нужный момент. Это позволяет агенту «помнить» контекст между сессиями и применять проверенные сценарии без повторного обучения модели.

## Current Understanding

### Три уровня «знания» агента

1. **Память (memory)** — короткие факты о среде, пользователе, принятых решениях. Загружается в контекст почти всегда.
2. **История сессий (session log)** — полная история диалогов, индексируется полнотекстовым поиском (FTS5). Подгружается по запросу через инструмент `session_search`.
3. **Навыки (skills)** — длинные пошаговые инструкции для повторяемых задач, оформляются как отдельные файлы (`SKILL.md`). Агент может создать навык сам, если успешно решил сложную задачу.

### Память в Hermes (как основной референс)

Два файла:

- `MEMORY.md` — короткие факты о среде и решениях.
- `USER.md` — предпочтения пользователя, особенности взаимодействия.

Объём **намеренно ограничен** — это не дамп переписки, а краткие утверждения.

### Навыки в Hermes

- Хранятся как обычные файлы — можно открыть, проверить, изменить, удалить.
- Устанавливаются из каталога Skills Hub.
- Переносимы между совместимыми агентами.
- Не зашиты в саму модель — это управляемая версионируемая база знаний.
- Совместимы с открытым стандартом `agentskills.io`.

### Поиск по истории

- Полная история хранится отдельно от памяти.
- Инструмент `session_search` (FTS5) делает полнотекстовый поиск по прошлым сессиям.
- LLM-пересказ найденного даёт «контекстный возврат» к произвольному прошлому разговору.

### Когда что использовать

- **MEMORY.md / USER.md** — для вещей, которые должны влиять на каждый запрос (имя пользователя, стек, имя VPS).
- **Навык** — для повторяемой процедуры, которую легко забыть или сделать с ошибкой (деплой на Amvera, проверка Docker-контейнера, разбор инцидента).
- **`session_search`** — когда нужно вспомнить конкретный прошлый разговор.

### Расширения в Hermes v0.21 (Pantheon Release)

- **Cron с памятью** — scheduled jobs загружают и обновляют persistent memory. `continuity=true` несёт output предыдущего run в следующий, monitor-mode jobs пропускают LLM если ничего не изменилось.
- **Bot Mode memories** — каждая роль агента в Bot Mode имеет собственный набор памяти и навыков.
- **Honcho dialectic user modeling** — формирование «диалектической» модели пользователя через диалоги.
- **Per-job durable notepads** — у каждой cron-job есть свой scratchpad.

### Альтернативные реализации

- **Windsurf Memories** — Cascade автономно накапливает знания о конвенциях проекта. Можно дополнить explicit rules в `.windsurf/`. Минус: нет инструмента для аудита/чистки.
- **OpenClaw Skills** — `~/.openclaw/workspace/skills/<name>/SKILL.md`. AGENTS.md/SOUL.md/TOOLS.md как injected prompt files.
- **Cursor Rules** — постоянный контекст через `.cursor/rules`. Более «статичный» подход, без авто-накопления.
- **Этот vault (`raw/` + `wiki/`)** — реализация концепта для LLM-куратора, по образцу LLM Wiki (см. [[wiki/concepts/llm-wiki-template]]).

## Contradictions / Uncertainty

- Граница между «памятью» и «навыком» размыта: навык можно частично загрузить в память, но тогда он быстро съест контекст.
- «Самообучение» в маркетинге агентов часто смешивают с fine-tuning — это **разные вещи**. В нашей базе считаем, что память/навыки ≠ fine-tuning.
- Memory staleness в Windsurf (нет prune-инструмента) — открытая проблема.
