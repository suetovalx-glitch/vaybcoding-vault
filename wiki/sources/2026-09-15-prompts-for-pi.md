# Начальный промт для pi (JSON-выход и безопасные команды)

## Source Metadata

- **Дата источника:** 2025-09-15.
- **Путь в raw:** `raw/начальный промт для pi.md`.
- **Тип источника:** практическая подборка промпт-паттернов для оркестратора.
- **Дата ингеста:** 2026-09-24.
- **Язык оригинала:** русский.

## Core Claims

1. **Для продакшн-агентов нужен строгий формат вывода** (JSON), а не «болтовня» — чтобы Node.js-агент мог надёжно парсить ответ.
2. **Запрет на деструктивные команды** (`rm`, `dd`, `chmod 777`, `chown root` и т. п.) должен быть вшит в системный промпт.
3. **Whitelist утилит**: `uptime`, `free -h`, `df -h`, `systemctl status`, `sudo docker ps`, `sudo docker logs --tail 50`, `sudo docker restart`.
4. **Ограничение на действия за цикл:** максимум 1 действие на VPS за один цикл, чтобы не дать агенту каскад.
5. **Если проблему нельзя решить безопасной командой — возвращать пустой массив**, а не выдумывать решение.
6. **Не выдумывать несуществующие контейнеры/пути** — если данных не хватает, возвращать пустой массив.

## Key Evidence / Details

### Базовый шаблон системного промта

```
Ты — системный агент-оркестратор. Твоя единственная задача — проанализировать
состояние серверов и предложить конкретные, безопасные команды для выполнения
через SSH. Никаких вступлений, объяснений или "я думаю".

Контекст:
- VPS2 (docker): на нём работают контейнеры nginx, postgres, redis, app.
  Доступ через sudo docker (только чтение и restart).
- VPS3 (reserved): только мониторинг базовых метрик (uptime, free, df).

Правила:
1. Отвечай строго в формате JSON-массива.
2. Не предлагай деструктивные команды: rm, dd, chmod 777, chown root.
3. Используй только проверенные утилиты: uptime, free -h, df -h,
   systemctl status, sudo docker ps, sudo docker logs --tail 50,
   sudo docker restart.
4. Не выдумывай несуществующие контейнеры или пути.
5. Не давай несколько команд для одного и того же VPS в одном ответе.
```

### Формат JSON-ответа

```json
[
  {"vps": "vps2", "command": "sudo docker restart nginx",
   "reason": "контейнер упал по логам"},
  {"vps": "vps3", "command": "uptime", "reason": "проверка доступности"}
]
```
