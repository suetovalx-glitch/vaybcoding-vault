## Контекст

Продолжение сессии 01. Пользователь уточнил: переезжать нужно не только vault, но и **самого агента-ассистента** (pi-coding-agent) с ноутбука на VPS, с сохранением данных. Тот же план в `задумки-проект/`.

## Что обсудили

- Что считаем «агентом» под переезд: среда (pi-coding-agent), LLM-конфиг, контекст и память, tool/MCP-конфиг, vault, окружение.
- Принципы: сначала vault, потом агент; GitHub — единый источник истины; конфиги в Git без секретов; smoke-test перед выключением ноутбука.
- 11 фаз: решения, vault, среда VPS, экспорт конфигов, установка, systemd, SSH, безопасность, cron, smoke-test, документация, опциональные расширения.

## Принятые решения

- Три варианта доступа к агенту: CLI по SSH, web-gateway, Telegram-бот. Начать с CLI.
- Пользователь `agent` на VPS, непривилегированный.
- API-ключи только в `~/.config/pi/secrets.env` с правами 600, **отдельные** для ноута и VPS.
- Systemd-unit с sandbox-ограничениями (PrivateTmp, ProtectSystem=strict).
- Только SSH-ключи, root по паролю закрыт, порт сменён на 22022.
